\section{大语言模型如何生成文字？从概率、采样到缓存}
\label{intro:23-llm-systems}

\subsection{从预测下一个 Token 到预训练}

假设文本为：
\[
\text{“今天 天气 很 好”}.
\]
预训练时，模型看到“今天”，预测下一个 Token；看到“今天 天气”，预测“很”；以此类推。训练目标不是要求模型“背诵一个固定答案”，而是\textbf{对真实下一 Token 分配更高概率}。

如果真实 Token 的模型概率为 $p_{\rm true}$，单个位置常用的损失是：
\begin{equation}
\boxed{L=-\log p_{\rm true}.}
\end{equation}
例如 $p_{\rm true}=0.8$ 时损失约 $0.223$，若 $p_{\rm true}=0.1$ 则损失约 $2.303$。真实 Token 被赋的概率越低，损失越大。这叫\textbf{交叉熵}在单个 one-hot 目标上的形式。

\textbf{预训练}是在大量数据上学习通用的语言与世界模式；\textbf{微调}是在已有权重上进一步训练特定任务或行为；\textbf{推理}则是训练结束后使用权重生成结果。

\subsection{后训练与生成不是一件事}
\textbf{预训练}学习一般 Token 预测模式，\textbf{后训练}利用示范答案、偏好或奖励调整模型行为；\textbf{推理}使用当前权重生成结果。SFT、RLHF、RLVR 与 CoT 的具体区别，见\hyperref[intro:23c-post-training]{后训练章节}。

\subsection{下一 Token 不是一定取最高概率}

假设模型对三个候选 Token 的预测概率是：
\[
p=(0.6,0.3,0.1).
\]
\textbf{贪心解码}总取 $0.6$ 对应的候选；\textbf{采样}则可以按概率随机选取。常用参数：
\begin{enumerate}
\item \textbf{Temperature（温度）}：把 logits 除以温度再做 Softmax；温度低通常使分布更尖锐，温度高通常更平坦。
\item \textbf{Top-k}：先保留概率最高的 $k$ 个候选，再在其中归一化采样。
\item \textbf{Top-p}：按概率从高到低累加，保留达到设定累积概率阈值的一组候选，再采样。
\end{enumerate}
采样增加输出多样性，但\textbf{多样性不等于正确性}。温度调低也不能保证没有事实错误。

\subsection{上下文窗口、KV Cache 和推理成本}

上下文（context）是模型当前可利用的输入 Token 序列。模型的最大上下文窗口限制每次处理的长度；长上下文不保证模型能完美回忆每个细节。

解码器逐 Token 生成时，过去 Token 的注意力 Key/Value 不必每次都重新计算。\textbf{KV Cache}保存这些中间结果，使后续生成可复用；但缓存会占用内存，且会随层数、头数和上下文长度增加。

\subsection{为什么语言模型会出现幻觉？}

语言流畅和事实可靠是两种不同的性质。模型会根据统计模式输出概率较高的文字，并不内置对所有事实的实时验证机制。它可能自信地生成错误的人名、数字或引用。

\textbf{检索增强生成（RAG）}的一条典型流程是：
\[
\text{问题}\to\text{检索文档}\to
\text{把相关片段放进上下文}\to\text{模型生成答案}.
\]
检索可以来自\textbf{网页、文件库、数据库或内部知识库}，不限于私有数据，也不要求一定使用向量数据库。Embedding 相似度搜索是常见检索方式之一。

\textbf{向量检索}的一种常见做法是：将问题与候选文本都表示成向量，通过点积或余弦相似度寻找相关内容。实际 RAG 系统也可能结合关键词检索、元数据过滤和重排序，并非只能采用向量检索。

\begin{warningbox}
RAG 提供外部证据，\textbf{不能自动消除幻觉}：检索可能漏掉正确文档，文档也可能过期、错误或被误读。可信系统需要引用、核验和必要的权限控制。
\end{warningbox}

\subsection{从模型到外部系统}
模型产生工具调用请求，并不等于模型亲自执行了程序。\textbf{Agent} 系统还需要工具运行环境、权限、状态与结果检查。参见\hyperref[intro:23d-agent-systems]{Agent 设计章节}。

\subsection{开放权重不一定等于完全开源}

\begin{center}\small
\begin{tabularx}{\linewidth}{@{}p{30mm}X@{}}\toprule
说法 & 需要检查的内容\\\midrule
闭源服务 & 通常只提供调用界面，不开放完整模型权重\\
开放权重 & 模型权重可获取，但训练数据、代码或许可可能有限制\\
开源模型 & 要检查代码、许可、训练细节和可复现程度；不能只看宣传名称\\
本地部署 & 在自己的设备运行模型，并不必然意味着模型可自由修改或再分发\\
\bottomrule\end{tabularx}
\end{center}

\begin{conclusion}
从训练到应用的主线是：\textbf{预测 Token 的目标训练出参数；解码策略利用参数生成内容；检索和工具为模型补充外部信息与执行能力。}把模型本身和外部系统分开理解，就不会被术语混淆。
\end{conclusion}

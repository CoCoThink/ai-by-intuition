\subsection{先数一数：主模型有多少个可训练参数？}
\phantomsection\label{app:parameter-count}

运行脚本前先手算。主模型的参数是：$E:5\times3$、$P_{\rm pos}:3\times3$，
四组 $3\times3$ Attention 投影（$W_Q,W_K,W_V,W_O$）、$3\times4$ 与 $4\times3$ 两张 FFN 矩阵、
一个 $3\times5$ 输出头。忽略固定的 LayerNorm 与中间激活，可训练元素共有多少个？
若输出头改为与 $E$ 共享权重，输出头应取什么形状，独立存储的参数又剩多少？

\noindent{\small\textbf{核对（先遮住）：}$15+9+4\times9+12+12+15=\answerresult{99}$，
与\hyperref[eq:toy-99-parameters]{正文参数总数公式}一致，脚本也会打印 \texttt{Parameters: 99}。
共享时输出头写作 $E^\top:3\times5$，独立存储 $99-15=84$ 个；这改变了结构，
$E$ 的梯度要把查表与输出头两条路径相加，不能只在总数里扣掉 15 而保持原计算不变。}\par

\textbf{自动求导关键步骤（节选）：}
\begin{verbatim}
loss_before, z_before = forward()
loss_before.backward()
with torch.no_grad():
    for value in weights.values():
        value -= LR * value.grad
        value.grad.zero_()
loss_after, z_after = forward()
\end{verbatim}
这里展示梯度的收集与同步更新；模型初始化、因果 Attention、
两次 LayerNorm、FFN 和断言保留在
\ifdefempty{\bookbuildfullsha}{\path{scripts/pytorch_starter.py}}{%
\href{https://github.com/CoCoThink/ai-by-intuition/blob/\bookbuildfullsha/scripts/pytorch_starter.py}{同一提交的完整可运行脚本}}，避免纸质版印出数十行维护性代码。

脚本采用双精度以便与 NumPy 手算基线按容差对齐。观察代码时请检查：
\texttt{E[ids - 1]} 是三行查表，
\texttt{triu} 保证因果掩码，
\texttt{cross\_entropy} 使用 \texttt{targets - 1} 并对三行取平均，
\texttt{backward} 将梯度送回所有可训练矩阵，
最后一次性更新全部九组参数。
每次重新运行都从同一份初值开始。

\textbf{把 ID 与数组下标逐项对齐。}
五项词表依次是“其他、春天、。、花、开了”，输入 ID 是 $[2,4,5]$，
目标 ID 是 $[4,5,3]$；代码中仅在索引时转换为 $[1,3,4]$ 与 $[3,4,2]$。
因此 \texttt{probs[0,3]} 是第一位置预测“花”（ID 4）的概率，
而 \texttt{probs[1,4]} 是第二位置预测“开了”（ID 5）的概率。
\begin{verbatim}
python3 scripts/teaching_reference.py --json
\end{verbatim}
参考实现同时核对语义、首尾 ID 查表、目标列及梯度；本例第一位置正确类概率
从 $0.261653$ 升至 $0.326865$，第二位置从 $0.050747$ 升至 $0.068548$。

PyTorch 自动求导与 NumPy 手工反传是\textbf{两种独立实现途径}；跨硬件和 Torch 版本时，浮点结果按数值容差比较。

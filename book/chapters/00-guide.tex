\section*{阅读指南：我们能否一步步设计出一个语言模型？}
\addcontentsline{toc}{section}{阅读指南：我们能否一步步设计出一个语言模型？}

\begin{idea}[title={先给整本书一个问题}]
如果让计算机读到“春天，花”，它怎样推测后面可能接“开了”？
我们不打算一开始就拿出庞大的 Transformer 图，而是从
\textbf{函数和几个数字}出发，逐层解决理解、计算与训练的问题。
你可以从这里开始建立直觉，不必先完整学过线性代数和神经网络。
\end{idea}

\subsection*{同一个小故事，贯穿整条计算链}

为了让后面的公式有归属，我们反复使用一个\textbf{人为设计}的例子：
\[
\text{“春天”}\ \longrightarrow\ \text{“花”}\
\longrightarrow\ \text{“开了”}\ \longrightarrow\ \text{“。”}
\]
假设分词器把这四项当成四个 Token，编号为
$[1,3,4,2]$。这个词表、编号和向量只为方便手算，
\textbf{不是某个真实语言模型的参数或分词结果}。

你会看到同一件事如何逐渐增加结构：
\begin{enumerate}
\item \textbf{先能表示：}文字变成 Token ID，再变成向量和矩阵。
\item \textbf{再能计算和学习：}用 MLP 得到预测，
通过损失、梯度和反向传播修改参数。
\item \textbf{发现新的困难：}单独看“花”这个向量，
不能充分说明它和“春天”“开了”的关系。
\item \textbf{让信息交流：}比较不同位置的相关性，
通过 Attention 选择性地读取上下文。
\item \textbf{形成完整系统：}组装 Transformer，
学习错位标签、因果掩码、下一 Token 的概率与生成，
最后才讨论缓存、现代架构与 Agent。
\end{enumerate}

\subsection*{哪部分先读，哪部分可以选读？}

\textbf{前五部分是一条连续主线。}
每个新章节都在回答前一章留下的问题。
例如学完 Embedding，就要追问“词与词如何交换信息”；
学完 Attention，就要追问“怎样让整个序列同时计算”；
理解生成后，再讨论 GQA 为什么节约 KV Cache。

\textbf{第六部分是选读和查阅区。}
CNN 解释另一类输入数据的空间结构；
联想记忆从外积、干扰和 Key--Value 重新推导
与注意力相似的数学结构；高维记忆容量有特定随机性假设。
这些都值得学习，\textbf{但不要求你先学它们才能进入 Transformer}。
章末的术语地图可以点击“见第×章”返回解释源头。
正文中再次提到重要概念时，蓝色术语可点击返回\textbf{首次完整解释}的位置；
同一章不会把每次重复出现的词都做成链接，以免干扰阅读。

\subsection*{每次遇到一个新公式，先问三件事}

\begin{enumerate}
\item \textbf{为什么需要它？}当前方法遇到了什么具体困难？
\item \textbf{数字怎样流动？}输入和输出的尺寸是多少，
每一步是点积、逐元素函数，还是加权求和？
\item \textbf{它的适用范围是什么？}数学恒等式、统计趋势
与模型设计选择不能混为一谈。
\end{enumerate}

\begin{warningbox}
\textbf{图和公式都有“摆放约定”。}单个 Query 可以写成列向量，
批量 Token 通常每行一个。遇到 $Kq$、$QK^\top$ 或 $V^\top a$，
先检查行列，必要时回看矩阵乘法章的双色图卡。
不必把转置当成新算法。
\end{warningbox}

\begin{conclusion}
学这本书，不是按顺序收集专业名词，
而是把“怎样预测下一个 Token”逐步拆成
\textbf{表示 $\to$ 计算 $\to$ 学习 $\to$ 上下文
$\to$ 组装 $\to$ 训练与生成}。
每学完一步，自然会产生下一步的问题。
\end{conclusion}

\section{会接龙，还要怎样学会对话与解决任务？}
\label{intro:23c-post-training}
\chaptercompass{续写能力怎样进一步对齐任务要求？}{区分 SFT、偏好信号、可验证奖励与推理时计算。}{示范／奖励／候选 $\to$ 不同训练或验证路径}{SFT、奖励学习会更新参数；CoT 提示本身通常不会}
\modelpipelinefocus{0}{后训练目标与反馈}


\begin{idea}
\noindent\emph{任务目标改变，训练信号也需要改变}\par

模型即使能在上下文中模仿报表格式，仍可能编造来源或漏掉单位。
\textbf{任务完成质量}要求清楚的目标和反馈：
遵守格式、核对证据、处理不确定性。
这里比较监督微调、偏好学习、可验证奖励和推理时策略
如何分别改变模型或生成过程。
\end{idea}

\subsection{预训练与监督微调：看起来都是预测 Token，但哪一项变了？}
\phantomsection\label{concept:sft}

预训练使用文本中的后续 Token 作为目标；
监督微调（SFT）使用特定任务的输入和示范答案。
数学上，两者都可能继续使用 Token 级 \conceptlink{cross-entropy}{交叉熵}，
但数据如何构造、哪些位置计入损失不同。

例如训练对话数据为：
\[
\text{用户：$2+3=?$}\qquad
\text{助手：$5$}.
\]
常见做法是把用户提问作为条件，
重点让助手回答的 Token 参与损失；
也可以按实际训练目标选择不同掩码。
这样模型不仅学语言续写，还学习
在给定指令和角色约束下如何回应。

\subsection{偏好学习：一个问题可能有很多语法正确的答案}
\phantomsection\label{concept:rlhf}

面对“请解释什么是梯度”，回答 A 可能准确、循序渐进，
回答 B 虽流畅却有明显错误。
两种回答都可以由语言模型生成，
但我们希望让更有帮助、事实更可靠的回答得到更高偏好。

基于人类反馈的强化学习（RLHF）是一类利用偏好或评价信号
优化模型行为的方法。某些流程会训练\phantomsection\label{concept:reward-model}奖励模型，再对语言模型做策略优化；
也有与强化学习不同的直接偏好优化方法。
偏好数据不等于客观真理：标注者可能有分歧，
偏好模型也会出现偏差。

\subsection{成对偏好怎样变成训练信号？}
把回答 A 与回答 B 的奖励分数分别设为 $r_A=1$、$r_B=0$。
一种用于\textbf{成对偏好建模}的简单概率是
\[
P(A\succ B)=\sigma(r_A-r_B)
=\frac{1}{1+e^{-1}}\approx\boxed{0.731}.
\]
若偏好标签是“A 优于 B”，负对数损失为
\[
-\log P(A\succ B)\approx\boxed{0.313}.
\]
这是成对偏好建模的一种损失。进入策略优化时，还可能结合采样、优势估计与约束。

\subsection{可验证奖励：让模型在能自动检查的任务中尝试改进}
\phantomsection\label{concept:grpo}
\phantomsection\label{concept:rlvr}

对于一部分题目，我们可以编写\textbf{自动核验结果}的程序。
例如问题是计算 $17+25$，提交答案 $42$ 可以得奖励 $1$，
提交其他答案得 $0$。
这类信号可以用于基于可验证奖励的强化学习（常见缩写 RLVR）。

\begin{center}
\begin{tikzpicture}[>=Latex,node distance=5mm,
 n/.style={draw=linegray,rounded corners=3pt,fill=paper,minimum width=108mm,minimum height=10mm,align=center,font=\small}]
\node[n] (q) {问题：$17+25$；模型采样一个候选答案};
\node[n,below=of q] (v) {验证器执行规则：答案是否为 $42$？};
\node[n,below=of v] (r) {奖励信号 $\to$ 学习算法更新模型策略};
\draw[->,thick,blue] (q)--(v);
\draw[->,thick,orange] (v)--(r);
\end{tikzpicture}
\end{center}

\begin{example}
\noindent\emph{算一组可验证奖励与相对优势}\par
若模型对同一道题独立生成四个答案 $(42,41,42,50)$，验证器给予奖励 $(1,0,1,0)$。本组平均奖励为 $\bar r=0.5$；一种直观的中心化相对信号是
\[
(r_i-\bar r)=(+0.5,-0.5,+0.5,-0.5).
\]
正确候选对应正信号，错误候选对应负信号；训练算法再利用这些信号更新策略。
\textbf{与 GRPO 的关系：}这是一种按组奖励中心化的教学化相对优势信号；
GRPO（Group Relative Policy Optimization）还涉及组内尺度处理、策略概率比、裁剪等具体训练细节，
不能将仅仅减去平均奖励的四个数字称为完整 GRPO 算法。
可对照 \href{https://arxiv.org/abs/2402.03300}{DeepSeekMath 的 GRPO 方法}
和 \href{https://arxiv.org/abs/2501.12948}{DeepSeek-R1 的强化学习实践}。
\end{example}

把自动验证用在更复杂的任务上，还需要检查答案格式、代码测试结果、奖励漏洞以及验证器本身的错误。

\subsection{“让模型写步骤”与“训练模型推理”不是一回事}
\phantomsection\label{concept:cot-prompt}

\textbf{思维链提示（Chain-of-Thought, CoT）}的一种常见形式
是要求模型先给出中间步骤，再给结果；
它可能帮助某些复杂任务，也可能产生冗余甚至错误的解释。
输出可见的推理文字并不保证这些文字真实反映了模型内部的全部计算过程。

\textbf{为什么写出步骤可能有用？}
对固定结构、固定长度的单次前向计算而言，模型每生成一个 Token 都经历有限的计算层。
如果把中间步骤写成新的 Token，后续 Token 就能读取这些步骤；
这相当于允许更多\textbf{串行的前向计算}参与解题。
它能够提高某些任务的成功率，却也会传播前一步错误、增加延迟和 Token 成本；
\textbf{可见文字不是对内部真实推理轨迹的忠实读出}。

要区分三种情况：
\begin{enumerate}
\item \textbf{提示策略：}改变输入指令，不修改参数。
\item \textbf{训练策略：}通过示范、偏好或奖励信号修改模型参数。
\item \textbf{推理时计算：}增加候选采样、验证或搜索步骤，
以更多计算换取一定条件下更高的解题成功率。
\end{enumerate}

训练效果应通过任务相关的独立测试与失败案例分析来检验。

\subsection{同一份季度报告任务：哪些改进需要训练？}

假设应用希望模型从\textbf{被授权的季度运营报告}中
逐一提取“营业收入、季度、币种和原表出处”，
最终做出不遗漏来源的比较。
我们可以区分以下改进方式：

\begin{itemize}
\item \textbf{只改 Prompt/Few-shot：}给两条“数值+单位+来源”示例，
让预训练模型模仿格式；每次请求可改变提示，但不会更新权重。
\item \textbf{使用 SFT：}收集经过人工核对的示范输出，
让模型经交叉熵学习遵守格式、在缺证据时拒绝臆测；
改变的是可训练参数，不能代替真实报表数据。
\item \textbf{偏好反馈：}在两条内容相近的回答中，
偏好明确列出原表来源、单位一致、承认缺失证据的一条。
偏好可能帮助行为选择，但本身不是财务数据真伪判定器。
\item \textbf{可验证奖励：}针对提取出的数值，用程序比较单位、
检查可验证的计算公式与来源格式；
只给正确格式奖励仍可能鼓励编造来源，因此验证内容很重要。
\end{itemize}

\textbf{共同的边界：}训练信号调整模型回答行为，
并不自动授予读取某个私有文件的权限。
实际检索文件、执行计算与引用核对属于下一章的系统工作。

\begin{conclusion}
理解一种模型改进方法，要看它使用什么目标和反馈、是否更新参数，以及如何评价结果。
从预训练到后训练，模型仍在利用可微计算与优化，
但训练数据和任务定义已经发生变化。
然而一个符合指令的模型仍不能自己读取指定文件、核验实时数据或执行程序。
下一章解释这些能力为什么属于模型之外的\textbf{工具与系统}。
\end{conclusion}

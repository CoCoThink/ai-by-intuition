\section{从文字到向量：先分 Token，再查 Embedding}
\label{intro:20-embeddings}

前面学会了向量和矩阵，但还有一个问题：
\textbf{文字不能直接参与点积，怎样让同一段文字成为一张数字表？}
我们先认识每个输入位置的身份，再让每个身份对应一条可训练向量。
这条转换链是\textbf{文本 $\to$ Token $\to$ ID $\to$ Embedding}。

\subsection{第一步：Token 与 Tokenizer 是什么？}
\phantomsection\label{concept:token}

\textbf{Token} 是模型处理文本时采用的离散单位，
可以是一个字、一个词、词的一部分或标点。
\textbf{Tokenizer（分词器）}规定怎样把原始文本拆成 Token，
并从词表中查出对应的整数 ID；不同分词方案可能得到不同的切分结果。

继续使用贯穿全书的\textbf{人工教学词表}，
假设它只有五个编号，其中四个对应：
\[
\begin{array}{c|ccccc}
\text{ID}&0&1&2&3&4\\\hline
\text{Token}&\text{其他}&\text{春天}&\text{。}&\text{花}&\text{开了}
\end{array}
\]
其中“其他”只是为编号 $0$ 放置的示意候选，
并非真实分词器通用的特殊标记。
于是
\[
\text{“春天 / 花 / 开了 / 。”}
\quad\longmapsto\quad [1,3,4,2].
\]
\textbf{编号只回答“是哪一个 Token”}。
不能因为 $4>1$，就说“开了”比“春天”更重要或语义更强。

\subsection{第二步：One-hot 怎样表示 Token 的身份？}

如果词表有五个候选，\textbf{One-hot（独热编码）}
就用五个数字表示某个 ID，只有相应位置为 $1$，
其余位置都是 $0$：
\[
\text{ID 1}\ \mapsto\
\begin{bmatrix}0\\1\\0\\0\\0\end{bmatrix},
\qquad
\text{ID 3}\ \mapsto\
\begin{bmatrix}0\\0\\0\\1\\0\end{bmatrix}.
\]
它能区分身份，但两条不同的 One-hot 向量点积都是 $0$；
\textbf{光靠这个身份标签，还没学到词与词的关系。}
而且真实词表可能很大，不会为了每次查词都显式创建这么长的稀疏列向量。

\subsection{第三步：Embedding 表让每个 Token 有一条短向量}
\phantomsection\label{concept:embedding}

给每个 Token 学习一条长度为 $d$ 的向量；
将它们\textbf{按行}堆起来，就是
\textbf{Embedding（嵌入）表}。
例如暂定 $d=2$，人工给出一张 $5\times2$ 的表：
\[
E=
\begin{bmatrix}
0&0\\
1&0\\
0&-1\\
0&1\\
1&1
\end{bmatrix}
\quad\in\R^{5\times2}.
\]
读第 $1$ 行（ID 1，春天）得到 $(1,0)$；
读第 $3$ 行（ID 3，花）得到 $(0,1)$；
读第 $4$ 行（ID 4，开了）得到 $(1,1)$。

注意这里说的“第 $1$ 行”是\textbf{从编号 $0$ 开始的行索引}，
即肉眼从上往下数的第二行。
为了避免混淆，更准确的说法是
\textbf{“读取 ID 为 1 的那一行”}。

那么前三个输入 Token $[1,3,4]$ 查表后得到：
\begin{equation}
\boxed{X=
\begin{bmatrix}
1&0\\
0&1\\
1&1
\end{bmatrix}\in\R^{3\times2}.}
\label{eq:running-embedding}
\end{equation}
\textbf{三行对应三个位置，每行有两个数字。}

\subsection{为什么查 Embedding 与矩阵乘法是同一回事？}

用 ID 3（“花”）的 One-hot 向量 $\vect u_3$；按行排列时计算 $\vect u_3^\top E$，如为了手算暂时竖写，它的转置形式才是 $E^\top\vect u_3$：
\[
\underbrace{E^\top}_{2\times5}
\underbrace{\vect u_3}_{5\times1}
=
\underbrace{\begin{bmatrix}0\\1\end{bmatrix}}_{2\times1}.
\]
所以“按 ID 查一行”和“用 One-hot 选出一行”在数学上等价。
实际程序通常直接查表，不必先造出一个长 One-hot 向量。

\begin{warningbox}
这些二维数字是\textbf{为了教学而编的}，并非“春天”和“花”的真实语义。
真实 Embedding 的表项是\textbf{训练中调整的参数}，
向量相近也不能直接证明事实、语义关系或推理能力完全相同。
\end{warningbox}

\subsection{只有词向量够不够？还有顺序问题}

把“花 / 开了”与“开了 / 花”的两个向量\textbf{无序相加}，
得到的数字相同，因为加法可以交换：
\[
\vect x_{\text{花}}+\vect x_{\text{开了}}
=
\vect x_{\text{开了}}+\vect x_{\text{花}}.
\]
但两段文本的顺序不同，意思也未必一样。
因此除了知道\textbf{每个 Token 是什么}，
还需要知道\textbf{它处在哪个位置、与别的位置怎样联系}。

\begin{conclusion}
从原始文字到可计算矩阵，我们已经有完整通路：
\textbf{Tokenizer 切分 $\to$ ID 表示身份 $\to$ Embedding 查表 $\to$ 向量按行堆叠}。
但我们还没有给网络规定\textbf{该用这些数字完成哪道练习题}。
下一章就把“学习语言”变成有输入、有答案的训练任务。
\end{conclusion}

\section{把语言练习变成一道可计算的预测题}
\label{intro:20b-task-contract}

阅读指南已经解释了\textbf{为什么选择下一 Token 预测来学习语言模式}：
原始文字自身能提供下一位置的训练答案，而把新 Token 接在后面，
又可以一步步生成较长的文本。
现在我们已有 Token ID 和 Embedding 向量，
就把这个\textbf{教学任务具体化}：给模型什么数字？希望它输出什么？
注意，我们并没有声称这样训练就能自动得到可靠的对话助手。

\subsection{贯穿全书的小例子}

假设一个只有 $5$ 个 Token 的教学词表，
其中四个 Token 对应
\[
\text{春天 / 花 / 开了 / 。}
\]
并约定编号为
\[
(t_1,t_2,t_3,t_4)=(1,3,4,2).
\]
在实际模型中 Token 不一定按词切分，
这些数字也不是某个分词器的真实编码。

我们希望读到“春天”时能预测“花”，
读到“春天、花”时能预测“开了”。
因此把一段数据\textbf{错开一个位置}：
\[
\underbrace{[1,\ 3,\ 4]}_{\text{输入 Token}}
\quad\longrightarrow\quad
\underbrace{[3,\ 4,\ 2]}_{\text{对应的下一 Token}}.
\]
这三个对应关系就是三道\textbf{由原始文本自动构造的练习题}。
例如第一题的输入是“春天”，期望候选是“花”；
第二题的输入已经多了“花”，希望预测“开了”。
这和前一章那张 $5\times2$ 的 Embedding 表连接起来了：
模型现在可以把输入 $[1,3,4]$ 查成三行二维向量，
接下来要学的是\textbf{怎样通过可训练的网络把每一行变成词表候选分数}。
此时比较的是\textbf{预测是否符合真实文本}，而不是机器是否理解了春天。
\textbf{为什么能在同一次前向计算中同时训练三个位置}，
要等学会 Attention、因果掩码和损失函数后再解释。

\subsection{先约定输入，再约定预测的输出}

\textbf{输入：}把已知文字表示成可计算的向量。
假设每个 Token 用 $2$ 个数字表示，
那么 Embedding 表的形状是
\[
\underbrace{5}_{\text{词表大小}}
\times
\underbrace{2}_{\text{每个向量的数字数}}.
\]
三个输入 Token 查表后可以组成 $3\times2$ 矩阵：
\textbf{三行表示三个位置，每行两个特征}。

\textbf{输出：}针对下一位置的候选给出预测分数。
无论网络内部进行了多少运算，最终都需要
\textbf{为五个候选 Token 分别提供一个分数}，
然后才能比较候选或选择结果。
此时不用知道输出头如何实现，只需知道\textbf{任务目标}。

\begin{center}
\small
\begin{tabularx}{\linewidth}{@{}p{30mm}p{30mm}X@{}}
\toprule
对象 & 示例尺寸 & 为什么是这个数\\
\midrule
输入 Token ID & $3$ 个整数 & 有 3 个已知位置\\
Embedding 表 & $5\times2$ & 词表 5 项，每项 2 个特征\\
输入向量矩阵 & $3\times2$ & 3 个位置，每行 2 个特征\\
每个位置的候选 & $5$ 个 & 词表共有 5 个可能的输出\\
\bottomrule
\end{tabularx}
\end{center}

\begin{warningbox}
“预测下一 Token”是本文为了学习自回归语言模型选定的任务，
并非所有 AI 模型都这样训练。分类、回归、图像生成等任务
有自己的输入输出与损失形式。
\end{warningbox}

\begin{conclusion}
我们已经把“学习语言”这个大问题缩成一个\textbf{有输入、有答案、能量化错误的练习任务}。
下一部分从一个小网络开始，解释\textbf{有参数的计算函数怎样根据答案逐步改进}；
至于怎样利用整段上下文，要等学完 Attention 再回来。
\end{conclusion}

\section{把语言练习变成一道可计算的预测题}
\label{intro:20b-task-contract}
\chaptercompass{训练下一 Token 时，输入与正确答案怎样对齐？}{把输入 ID 序列与右移一位的目标 ID 配对，再约定预测形状和评测。}{$[1,3,4]\to[3,4,2]$；每个位置的 logits 为 $1\times|\mathcal V|$}{任务契约不新增权重；后续模型中的 Embedding、投影等参数需训练}
\modelpipelinefocus{0}{训练样本与目标}

阅读指南已经解释了为什么选择下一 Token 预测来学习语言模式：
原始文字自身能提供下一位置的训练答案，而把新 Token 接在后面，
又可以一步步生成较长的文本。
现在我们已有 Token ID 和 Embedding 向量，
就把这个\textbf{教学任务具体化}：给模型什么数字？希望它输出什么？
这份事先写清\textbf{输入序列、目标标签、输出形状与评价方式}的约定，
叫做\textbf{任务契约（Task Contract）}。\phantomsection\label{concept:task-contract}它不需要额外训练一套网络，
而是避免把“给什么输入”和“模型应预测什么”混成一件事。


\subsection{贯穿全书的小例子}

假设一个只有 $5$ 个 Token 的教学词表，
其中四个 Token 对应
\[
\text{春天 / 花 / 开了 / 。}
\]
并约定编号为
\[
(t_1,t_2,t_3,t_4)=(1,3,4,2).
\]
在实际模型中，Token 也可能是一个字、词的一部分或标点。

我们希望读到“春天”时能预测“花”，
读到“春天、花”时能预测“开了”。
因此把一段数据\textbf{错开一个位置}：
\[
\underbrace{[1,\ 3,\ 4]}_{\text{输入 Token}}
\quad\longrightarrow\quad
\underbrace{[3,\ 4,\ 2]}_{\text{对应的下一 Token}}.
\]
这三个对应关系就是三道由原始文本自动构造的练习题。
例如第一题的输入是“春天”，期望候选是“花”；
第二题的输入已经多了“花”，希望预测“开了”。
这和前一章那张 $5\times3$ 的 Embedding 表连接起来了：
模型现在可以把输入 $[1,3,4]$ 查成三行三维向量，
接下来要学的是怎样通过可训练的网络把每一行变成词表候选分数。
此时比较的是\textbf{预测是否符合真实文本}，而不是机器是否理解了春天。
为什么能在同一次前向计算中同时训练三个位置，
分类交叉熵已在前面的三分类例子中推导；
Attention 和因果掩码将在后面解释。

\subsection{先看全图：Attention 是网络内部的上下文读取步骤}

可以先把整套语言模型理解为\textbf{一个可训练的大神经网络}：
ID 查表后，每个位置先有自己的向量；
Attention 让向量读到此前可见的其他 Token，
再经逐位置 FFN、输出头，得到词表候选分数。
这里的“给输入加上下文”指\textbf{模型内部的计算模块}，
不是额外联网插件；它不会自行读取外部私有资料。
训练还要在右侧用正确 Token 算损失，反向更新前面所有可训练权重。

\subsection{先约定输入，再约定预测的输出}

\textbf{输入：}把已知文字表示成可计算的向量。
根据统一主算例，每个 Token 用 $3$ 个数字表示，
那么 Embedding 表的形状是
\[
\underbrace{5}_{\text{词表大小}}
\times
\underbrace{3}_{\text{每个向量的数字数}}.
\]
三个输入 Token 查表后可以组成 $3\times3$ 矩阵：
三行表示三个位置，每行三个特征。

\textbf{输出：}针对下一位置的候选给出预测分数。
无论网络内部进行了多少运算，最终都需要
为五个候选 Token 分别提供一个分数，
然后才能比较候选或选择结果。
此时不用知道输出头如何实现，只需知道\textbf{任务目标}。

\subsection{一眼看懂这份任务的尺度}

本书此刻只用\textbf{3 个输入位置、5 个候选 Token、每位置 3 维特征}
定义训练任务。真实 GPT-2 small 的词表有 $50{,}257$ 项，
但目标仍是预测后续 Token。
这些数字先用来认识\textbf{输入、输出和目标的口径}；
完整模型与实际运行环境的规模对照在
\hyperref[intro:23a-from-toy-to-gpt]{第 27 章}集中给出。

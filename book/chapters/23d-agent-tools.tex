模型输出的是工具请求；文件修改、搜索和网络请求由外部程序执行，
并受工具配置、授权与安全策略约束。

同理，若用户询问前文“春天花开了”在\textbf{某日某地}是否属实，
模型可提出 \texttt{read\_observations} 请求（参数为日期与地点）；
应用（宿主）验证访问范围、日期与地点，再读带时间戳的数据。
后文把执行这些检查的程序统称为\textbf{应用}。
返回“未找到记录”是有效工具结果，\textbf{不是可以让模型编造“已开花”的许可}。
这和季度报告先查来源再算数字，属于同一套核证流程。

\subsection{请求和返回值长什么样？}

例如要读取一份允许访问的 Q3 教学报表，模型可以\textbf{提出}下述 JSON 请求；
\textbf{这是本书的应用层示意格式，不是任一厂商的可直接调用 API。}\texttt{id} 用于关联请求与结果；
应用程序仍需验证参数并决定是否执行：
\begin{tcolorbox}[colback=paper,colframe=linegray,boxrule=.5pt,arc=1mm,left=3mm,right=3mm]
\begin{Verbatim}[numbers=left,numbersep=4pt,fontsize=\footnotesize]
{"id":"call_q3_01","tool":"read_report",
 "arguments":{"quarter":"2026Q3"}}
\end{Verbatim}
\end{tcolorbox}
例如工具返回
\begin{tcolorbox}[colback=paper,colframe=linegray,boxrule=.5pt,arc=1mm,left=3mm,right=3mm]
\begin{Verbatim}[numbers=left,numbersep=4pt,fontsize=\footnotesize]
{"ok":true,"revenue":132,"unit":"million_CNY"}
\end{Verbatim}
\end{tcolorbox}
应用需要确认工具实际执行的结果，再把数据转交模型，
并核对数据来源、单位和授权范围。


\subsection{Agent loop：一次任务在消息里怎样向前推进？}
\phantomsection\label{concept:agent}
\textbf{Agent（智能体）}把模型放进一个由应用控制的循环：
模型读消息、提出下一步动作，应用授权并执行，再把结果交回模型。
本节采用一条便于追踪的规则：工具被拒绝或执行失败时立即停止，由应用报告缺失信息；
模型直接给出答复时，应用核验后交付，预算用尽时也由应用报告未完成状态。

前面的工具例子只展示了一次调用。下面把\textbf{模型提出动作、应用校验权限、工具返回结果、模型继续}写成一段可追踪的伪代码。
\begin{tcolorbox}[colback=paper,colframe=linegray,boxrule=.5pt,arc=1mm,left=3mm,right=3mm]
\begin{Verbatim}[numbers=left,numbersep=4pt,fontsize=\small]
messages = [system_message, user_message]
for step in range(MAX_STEPS):
    answer = model(messages, allowed_tools)
    messages.append(answer)
    if not answer.get("tool_calls"):
        return app_finish("answer", messages)
    for call in answer["tool_calls"]:
        if not is_authorized(call):
            result = {"ok": False, "error": "permission_denied"}
        else:
            result = execute_with_limits(call)
        messages.append(tool_message(call["id"], result))
        if not result["ok"]:
            return app_finish("tool_error", messages)
return app_finish("step_budget_exceeded", messages)
\end{Verbatim}
\end{tcolorbox}
这里用字典字段 \texttt{tool\_calls} 统一表示工具请求，某一真实接口的字段见\hyperref[elective:real-function-call]{本章选读}。

\texttt{execute\_with\_limits} 将超时等执行失败封装为 \texttt{ok=False}；
\texttt{app\_finish} 核验已有来源、数值与任务要求，返回完成状态或缺失清单。
它是应用逻辑，不额外调用模型；循环次数和权限检查也由应用控制。
这里一步指一次模型调用，同一次调用可以提出多个工具请求。
示例中使用本地模拟的“模型决策”，不连接外部 API。逐轮消息可记成：

\subsection*{再回到“春天 花 开了 。”：查证今天的花期}
仍以\hyperref[intro:23d-agent-systems]{前章那句“春天花开了”}为例。
用户问“今天甲园的花开了吗？”，这里需要核实的是\textbf{某一天、某个地点的观测}，
而不是计算续写“开了”的概率。按下面的工具记录逐步核查：
\begin{enumerate}[leftmargin=2em,itemsep=2pt]
\item \textbf{提出请求：}模型建议调用
\texttt{read\_observations(park="A", date="2026-04-06")}；
\item \textbf{检查权限：}应用核对用户允许的园区资料范围，才执行检索；
\item \textbf{返回证据：}工具找到“4 月 1 日盛开”和“4 月 5 日花期结束”
两份带日期的记录，却没有 2026 年 4 月 6 日的现场观测；
\item \textbf{交付结论：}系统可说明“4 月 5 日记录为花期结束，
4 月 6 日尚无直接观测”，并链接来源；4 月 1 日的照片只证明当日的花期。
\end{enumerate}
这段教学记录与季度收入例子共享同一组关口：
\textbf{明确任务 $\to$ 获得授权 $\to$ 返回有时效的证据
$\to$ 核查缺口 $\to$ 给出带来源的答案}。
既能复用最初的四个 Token，也展示了工具失败或证据不全时的正确处理。

\subsection{什么时候用固定工作流，什么时候用 Agent？}
\phantomsection\label{concept:workflow}

同样是处理报告，若每次步骤都固定为
“读取表格 $\to$ 计算增长率 $\to$ 套模板”，
\textbf{固定工作流}预先限定路径，便于逐步测试、审计和控制成本。

如果每次文件格式不同、需要动态选择工具，
而目标和安全边界仍能明确指定，
可以使用\textbf{带决策的 Agent 流程}。
但灵活度增加也意味着路径和结果更难完全预测。

\small

\begin{example}[breakable=false]
\noindent\emph{每轮循环都重读全部消息：输入 Token 怎样累积？}\par
\localfixture{教学用的固定消息长度，不对应某一分词器}
设系统与用户消息共 $80$ 个 Token，每条工具请求 $20$ 个、每条工具结果 $40$ 个。
前面的逐轮消息记录中，模型一共被调用 $4$ 次（三次请求工具，一次给出答复）。
第 $j$ 次调用要读入此前全部消息，长度为 $80+60(j-1)$：
\[
(80,140,200,260),\qquad
\text{合计 } 4\times80+60\times(0+1+2+3)=\boxed{680}\ \text{个输入 Token}.
\]
若模型在第一次调用中一并请求三份报表，只需两次调用：$80+(80+3\times20+3\times40)=340$ 个。
步数预算因此同时约束了时延与输入成本；
若 \texttt{read\_report(Q2)} 返回权限错误，循环在第 $2$ 次\textbf{模型调用}之后停止。
应用报告 Q2 缺失、Q3 尚未读取；这条状态报告不增加一次模型调用。
\end{example}
\subsection{\texorpdfstring{{\symboliconfont ★}}{★} 选读：一个真实函数调用接口的最小闭环}
\phantomsection\label{elective:real-function-call}

截至 2026-10-25（UTC），Claude Messages API 的客户端工具使用以下字段。
向 \texttt{POST /v1/messages} 提交的 JSON 必填 \texttt{model}、\texttt{messages}、\texttt{max\_tokens}，本例另带 \texttt{tools}。
配套脚本用 \texttt{Authorization: Bearer <API key>} 认证，发送 \texttt{content-type: application/json}
及 \texttt{anthropic-version: 2026-10-21} 请求头；跨工作区密钥还需 \texttt{anthropic-workspace-id}。
密钥类型与字段细节以附录 F 的官方文档为准。工具定义的核心字段为：
\begin{Verbatim}[fontsize=\small]
{"name":"quarter_growth",
 "description":"Compute growth from verified revenues in the same unit.",
 "input_schema":{"type":"object",
   "properties":{"previous":{"type":"number"},
                 "current":{"type":"number"}},
   "required":["previous","current"],
   "additionalProperties":false}}
\end{Verbatim}
名称标识工具，描述说明何时使用和业务含义，\texttt{input\_schema} 约束参数形状；
三者共同帮助模型选择工具与填写参数，执行权限由应用另外检查。
模型返回 \texttt{tool\_use} 内容块，其 \texttt{id}、\texttt{name} 和 \texttt{input}
分别表示本次请求、工具名和参数。应用检查工具白名单、数值及任务授权，
按已核验的 $120,132$ 计算出 $0.1$，再在下一条 \texttt{user} 消息中回传：
\begin{Verbatim}[fontsize=\small]
{"type":"tool_result","tool_use_id":"实际调用ID",
 "content":"{\"growth\":0.1,\"unit\":\"ratio\"}"}
\end{Verbatim}
下一次请求保留完整的 \texttt{assistant} 内容块和上述结果，模型据此继续。
只要 \texttt{stop\_reason} 仍为 \texttt{"tool\_use"}，就在预算内重复这一步；
取到 \texttt{"end\_turn"} 才按正常完成交付；长度截断与拒绝等其他停止原因分别处理。
这是真实接口的字段约定，示例数值仍来自本书季度报表。
完整最小客户端见 \path{scripts/claude_function_call_demo.py}；
直接运行只验证离线合成消息、ID 关联、计算与越权拒绝，\textbf{不调用在线模型}。
显式使用 \texttt{--real --model 模型ID} 并设置 \texttt{ANTHROPIC\_API\_KEY}，
才会进入有轮数上限的在线工具循环；运行记录应保存模型标识和日期。
字段依据\href{https://platform.claude.com/docs/en/api/messages/create}{官方 Messages API 文档}，
本书未将离线检查写成在线推理实测。

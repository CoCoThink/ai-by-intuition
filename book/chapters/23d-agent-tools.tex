模型输出的是工具请求；文件修改、搜索和网络请求由外部程序执行，
并受工具配置、授权与安全策略约束。

同理，若用户询问前文“春天花开了”在\textbf{某日某地}是否属实，
模型可提出 \texttt{read\_observations} 请求（参数为日期与地点）；
宿主应用验证访问范围、日期与地点，再读带时间戳的数据。
返回“未找到记录”是有效工具结果，\textbf{不是可以让模型编造“已开花”的许可}。
这和季度报告先查来源再算数字，属于同一套核证流程。

\subsection{请求和返回值长什么样？}

例如要读取一份允许访问的 Q3 教学报表，模型可以\textbf{提出}下述 JSON 请求；
\textbf{这是本书的应用层示意格式，不是任一厂商的可直接调用 API。}\texttt{id} 用于关联请求与结果；
应用程序仍需验证参数并决定是否执行：
\begin{tcolorbox}[colback=paper,colframe=linegray,boxrule=.5pt,arc=1mm,left=3mm,right=3mm]
\begin{Verbatim}[numbers=left,numbersep=4pt,fontsize=\footnotesize]
{"id":"call_q3_01","tool":"read_reports",
 "arguments":{"quarter":"2026Q3"}}
\end{Verbatim}
\end{tcolorbox}
例如工具返回
\begin{tcolorbox}[colback=paper,colframe=linegray,boxrule=.5pt,arc=1mm,left=3mm,right=3mm]
\begin{Verbatim}[numbers=left,numbersep=4pt,fontsize=\footnotesize]
{"ok":true,"revenue":132,"unit":"million_CNY"}
\end{Verbatim}
\end{tcolorbox}
应用需要确认工具实际执行的结果，再把数据转交模型，
并核对数据来源、单位和授权范围。

    \draw[draw=muted!55,densely dotted,line width=.4pt]

\begin{Verbatim}[numbers=left,numbersep=4pt,fontsize=\small]
messages = [system_message, user_message]
for step in range(MAX_STEPS):
    answer = model(messages, allowed_tools)
    messages.append(answer)
    if not answer.tool_calls:
        return answer.text
    for call in answer.tool_calls:
        if not is_authorized(call):
            result = {"error": "permission_denied"}
        else:
            result = execute_with_limits(call)
        messages.append(tool_message(call.id, result))
return {"error": "step_budget_exceeded"}
\end{Verbatim}
\end{tcolorbox}

\subsection*{再回到“春天 花 开了 。”：查证今天的花期}
仍以\hyperref[intro:23d-agent-systems]{前章那句“春天花开了”}为例。
用户问“今天甲园的花开了吗？”，这里需要核实的是\textbf{某一天、某个地点的观测}，
而不是计算续写“开了”的概率。下面是完全虚构的工具记录：
\begin{enumerate}[leftmargin=2em,itemsep=2pt]
\item \textbf{提出请求：}模型建议调用
\texttt{read\_observations(park="A", date="04-06")}；
\item \textbf{检查权限：}应用核对用户允许的园区资料范围，才执行检索；
\item \textbf{返回证据：}工具找到“4 月 1 日盛开”和“4 月 5 日花期结束”
两份带日期的记录，却没有 4 月 6 日现场观测；
\item \textbf{交付结论：}系统可说明“4 月 5 日记录为花期结束，
4 月 6 日尚无直接观测”，并链接来源，不把 4 月 1 日的照片当成当天证据。
\end{enumerate}
这段教学记录与季度收入例子共享同一组关口：
\textbf{明确任务 $\to$ 获得授权 $\to$ 返回有时效的证据
$\to$ 核查缺口 $\to$ 给出带来源的答案}。
既能复用最初的四个 Token，也展示了工具失败或证据不全时的正确处理。

\subsection{什么时候用固定工作流，什么时候用 Agent？}
\phantomsection\label{concept:workflow}

同样是处理报告，若每次步骤都固定为
“读取表格 $\to$ 计算增长率 $\to$ 套模板”，
\textbf{固定工作流}预先限定路径，便于逐步测试、审计和控制成本。

如果每次文件格式不同、需要动态选择工具，
而目标和安全边界仍能明确指定，
可以使用\textbf{带决策的 Agent 流程}。
但灵活度增加也意味着路径和结果更难完全预测。

\begin{center}
\small
\renewcommand{\arraystretch}{1.3}
\tagpdfsetup{table/header-rows={1}}
\begin{tabularx}{\linewidth}{@{}p{26mm}X@{}}
\toprule
组织方式 & 合适的情况与注意事项\\
\midrule
固定流程 & 步骤稳定，便于重复测试；变化过大可能需增添分支\\
Agent & 动态选工具和步骤；需要权限、预算与终止条件\\
Skill/操作指南 & 为某类任务提供步骤、示例与脚本；内容本身不是额外模型权重\\
Subagent/子任务分工 & 隔离部分上下文和工作；会带来协调与复核成本\\
\bottomrule
\end{tabularx}
\end{center}


\begin{example}[breakable=false]
\noindent\emph{工具读数之后再做算术}\par
工具返回 Q1 = $100$、Q2 = $120$、Q3 = $132$（百万元），程序计算：
\[
g_{Q2}=(120-100)/100=20\%,\qquad
g_{Q3}=(132-120)/120=10\%.
\]
如果 \texttt{read\_report(Q2)} 返回权限错误，程序记录 Q2 缺失，并停止依赖 Q2 的环比计算。
\end{example}
\chapterchecktasks{23d-agent-tools}{正文基础三题}{
\item \textbf{分工：}模型发出工具调用 JSON 后，由谁验证参数和权限？\chapterinlinehint{应用负责参数、权限校验与执行。}
\item \textbf{计算：}Q1、Q2、Q3 的收入是 $100$、$120$、$132$ 百万元，求两次环比增长率。若误把 Q1 作为 Q3 的基期，会得到多少？\chapterinlinehint{Q2 为 $20\%$、Q3 为 $10\%$；误用 Q1 得 $32\%$。}
\item \textbf{找错：}工具拒绝读取 Q2 时，Agent 自行补上 $120$ 并写“已核实”。哪一步失实？\chapterinlinehint{未经成功返回，却声称工具已核实。}
}
\chapterrecallanswer{模型只产生工具请求；应用执行、授权、错误处理与交付核对。}

\section{前文怎样传到当前词？从逐行处理到 RNN}
\label{intro:21a-context-gap}
\label{intro:21-rnn}

独立处理每个 Token 的 MLP，只接收当前位置的向量。
如果下一 Token 的正确预测还取决于\textbf{前面说过什么}，
一个只看当前位置的函数能区分这些不同上下文吗？

\subsection{同一个当前词，两段不同的前文}
\phantomsection\label{partq:context}

试着设计两条不同上下文：
\[
\text{“春天，花，开了”},\qquad
\text{“冬天，窗，开了”}.
\]
两段在最后位置都以“开了”结束，但后面的词
可以分别接不同对象或标点。这是说明“预测依赖上下文”的
\textbf{人为构造例子}，不是两句话的统计概率断言。
这里的“冬天”“窗”只用于上下文对照，不加入主线五项词表。

如果让一个相同的逐 Token MLP 只看“开了”的 Embedding，
它得到的输入都是同一个 $E[\text{开了}]$；
因为函数及参数也完全一样，两个上下文的输出就\textbf{必然一样}：
\[
f\bigl(E[\text{开了}]\bigr)
=f\bigl(E[\text{开了}]\bigr).
\]
它无法仅凭这一行区分不同前文。
要用 MLP 处理上下文，就要把前文也送进它的输入。

\subsection{一个无法靠背词表通过的对照任务}
\phantomsection\label{experiment:context-contrast}
取两条输入 $[\text{春天},\text{花}]$ 与 $[\text{冬天},\text{花}]$，
只监督第二位置：目标分别为“开了”和“谢了”。
将“春天／冬天／花”分别编码为三维 one-hot 向量，做一个二分类任务。
“谢了”也只作为本任务的输出类别，不加入主线词表；计算使用上述 one-hot 输入，而非前章的 Embedding 表。
两条样本的当前 Token 与位置都相同，
因此加上位置也无法帮助只看本行的 MLP 或只根据当前词预测下一个词的模型。
若两次输出“开了”的概率都为 $p$，平均损失是
\[
\begin{aligned}
L_{\rm local}&=-\tfrac12[\ln p+\ln(1-p)]
=-\tfrac12\ln[p(1-p)]\\
&\geq-\tfrac12\ln(1/4)=\ln2.
\end{aligned}
\]
因为 $p(1-p)\leq1/4$，增加逐位置网络容量也突破不了这个下界。
加入上下文读取后，输入才变得可区分。
能接收这些历史的固定窗口 MLP 或 RNN 也能拟合这两例。
\subsection{朴素办法：把前几个 Token 直接拼起来}

可以把最近三个 Token 的向量首尾拼接成一条长输入，
交给一个 MLP。这样它确实能看到这三个位置，
但只允许固定长度时，碰到第四个、更早的第十个位置又怎么办？
如果不断扩展拼接长度，输入参数量和位置处理办法也随之改变。
固定窗口 MLP 能解决一些任务，仍没有自然地复用任意前文的机制。

\subsection{新的问题：怎样把历史信息送给当前位置？}

我们需要让后一个位置\textbf{能利用}前面位置的信息，
而不是只做独立行变换。
下面先在本章后半段看一个容易理解的方案：沿序列传递一份不断更新的状态，这叫 RNN。
看完 RNN 后，下一章再尝试不经过一长串状态，直接读取某个位置。

固定窗口拼接、RNN 递推和直接读取这三种机制各有取舍；比较它们时，要把任务长度、数据、参数量和计算代价一起列入评测。

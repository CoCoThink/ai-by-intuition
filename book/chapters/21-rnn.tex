\chaptercompass{怎样把前一个 Token 的信息传给当前 Token？}{RNN 逐位置更新隐藏状态，把之前信息随时间传递。}{$x_t:1\times d_x,\ h_{t-1}:1\times d_h\to h_t:1\times d_h$}{$W_x,W_h,b$ 可学习；隐藏状态随输入改变，不是新训练权重}
\modelpipelinefocus{3}{RNN 的历史状态}

\begin{idea}
\noindent\emph{一份沿时间更新的状态}\par

RNN（循环神经网络）是一种按顺序处理输入的网络：
读到一个新 Token，就把\textbf{当前信息}和\textbf{上一步留下的状态}
一起送进\textbf{同一个更新函数}，算出新的状态；
再把这个状态交给下一步。

你可以先把状态理解成读到此刻为止的压缩笔记。
同一个更新函数在不同位置重复使用，状态则随输入不断变化。
\end{idea}

\subsection{怎样把上一章缺少的前文送进当前位置？}

上一章发现，只看当前 Token 的独立 MLP 不会凭空得到前文。
回到“春天、花、开了”这句话：
\[
\text{“春天”}\ \to\ \text{“花”}\ \to\ \text{“开了”}
\]
假设模型正在读第三个 Token“开了”，并尝试预测接下来是什么。
如果只让一个 \conceptlink{mlp}{MLP} 看到“开了”的 \conceptlink{embedding}{Embedding}，
它无法直接区分前文是“春天，花”还是完全不同的句子。

我们真正想要的是：读到第三个词时，已经保留一些前两个词的信息。
一种最直观的方案，就是让模型\textbf{依次阅读}，每次带着上一份笔记。

\subsection{用上一时刻的状态处理新输入}

RNN 依次进行三个状态更新：
\begin{enumerate}
\item 读第一个 Token，把它的信息写入一份状态（笔记）。
\item 读第二个 Token，参考第一步的状态，得到\textbf{更新后的}状态。
\item 读第三个 Token，参考第二步的状态，再得到新的状态。
\end{enumerate}

% 统一用后面的数值展开图，避免两幅高度重复的 RNN 时间图。

每一步都沿用同一组更新参数。后一位置必须等到前一位置的状态算完，才能继续。

\subsection{把更新函数缩到只有一个数字，真正手算一次}

假设每个 Token 已经转成向量，再从中取一个特征值用于手算：
\[
\text{春天：}x_1=1,\qquad
\text{花：}x_2=2,\qquad
\text{开了：}x_3=0.
\]
这些 $x_t$ 表示输入特征，与前面的 Token ID 不同。

只用一个数字记录状态。规定：
\[
\boxed{\text{新状态}=\text{本次输入}+0.5\times\text{旧状态}.}
\]
用 $h_t$ 表示读完第 $t$ 个位置后的状态，初始 $h_0=0$，
这条规则就是 $h_t=x_t+0.5h_{t-1}$。

\textbf{关键观察：}第三个输入是 $0$，但第三步的状态仍是 $1.25$。
这说明前文的信息经过状态传到了后面。
如果调换前两个输入，变成 $(2,1,0)$，
同样的规则得到 $h_1=2,\ h_2=2,\ h_3=1$。
输入数字相同，只是\textbf{顺序改变}，最后的状态就不同。

一个数字能保存的信息有限，但它已经展示出\textbf{状态怎样把过去的信息带到现在}。

\subsection{这和普通 MLP 最大的区别是什么？}

普通的逐 Token MLP 可以对三个输入\textbf{分别计算}；
它不会自动把第一个位置的计算结果送给第二个位置。
RNN 额外增加了从上一步状态到下一步状态的通路。

\subsection{用向量和矩阵写出 RNN}

把单个数字推广成向量，输入与状态就能包含更多特征。
我们约定：
\begin{itemize}
\item $\vect x_t$：第 $t$ 个 Token 的输入特征向量，长度为 $d_x$；
\item $\vect h_{t-1}$：读完前一个 Token 的状态，长度为 $d_h$；
\item $\vect h_t$：读完当前 Token 的新状态，仍为 $d_h$ 维；
\item $W_x$ 和 $W_h$：分别处理当前输入与旧状态的\textbf{可学习矩阵}；
$\vect b$ 是可学习偏置。
\end{itemize}
$d_x$ 表示输入特征数量，$d_h$ 表示状态特征数量。
典型的简单 RNN 更新式是：
\begin{equation}
\boxed{\vect h_t^\top=\tanh(\vect x_t^\top W_x+
\vect h_{t-1}^\top W_h+\vect b^\top).}
\label{eq:rnn-hidden}
\end{equation}
$\tanh$ 是\textbf{逐元素非线性函数}，
它把每个输入值映射到 $-1$ 与 $1$ 之间。
这里相当于先组合本次输入和旧状态，再经过非线性函数；
它不改变“沿时间传递状态”的核心直觉。

矩阵尺寸也能检查，依照主线的\textbf{每 Token 一行}约定：
\[
\underbrace{\vect x_t^\top}_{1\times d_x}
\underbrace{W_x}_{d_x\times d_h}
+
\underbrace{\vect h_{t-1}^\top}_{1\times d_h}
\underbrace{W_h}_{d_h\times d_h}
+\underbrace{\vect b^\top}_{1\times d_h}
\quad\longrightarrow\quad
\underbrace{\vect h_t^\top}_{1\times d_h}.
\]
若使用状态预测下一个 Token，
再乘以 $d_h\times|\mathcal V|$ 的词表权重就能得到候选分数。

\subsection{RNN 的限制，正好引出下一个问题}

上面的规则里，第一步的影响在第三步前就经过多次 $0.5$ 缩小。
随着状态多次更新，早期信息有衰减风险。
真实 RNN 的问题不只这一种：
长期依赖还面临梯度消失或爆炸的训练难题；
沿时间的状态更新也有\textbf{必须依次计算}的依赖。
LSTM 和 GRU 可以改善一部分信息保留问题，
但仍然使用递推机制。



\chapterchecktasks{21-rnn}{正文基础三题}{
\item \textbf{流程：}RNN 为什么需要隐藏状态？说明当前输入和前一时刻状态在递推式中如何共同决定下一状态。
\item \textbf{手算：}$h_t=x_t+0.5h_{t-1}$，$h_0=0$，输入依次为 $(2,0,1)$。依次求 $h_1,h_2,h_3$。
\item \textbf{预测：}把第一个输入由 $2$ 改为 $4$，其余仍为 $(0,1)$。不重新逐项推导全部式子，预测最终 $h_3$ 增大还是减小，变化多少？
}
\chapterrecallanswer{RNN 将历史压成逐步传递的状态，能携带前文，却通常需要串行执行，长依赖还可能衰减。}



\begin{conclusion}
RNN = 当前输入 + 上一步状态 $\to$ 同一个更新函数 $\to$ 下一步状态。
它解决“词与词如何沿顺序传递信息”，但每次必须经过中间状态。

如果当前词想直接查看很早以前的某个词，
怎样绕过中间的一长串状态，直接读取那个位置？
这就是下一章 Attention 要解决的问题。
\end{conclusion}

\subsection{先分清 Prompt、Context 与 Memory}

\phantomsection\label{concept:prompt}\textbf{Prompt（提示输入）}可以包含目标、约束、示例和当前问题；
\phantomsection\label{concept:context}\textbf{Context（上下文）}是本次请求可供模型读取的信息，
其中可以包含对话历史、检索片段和工具结果。

这里常说的\phantomsection\label{concept:app-memory}\textbf{应用记忆（Memory）}，指系统保存并再次提供的
历史摘要、偏好或事实，由应用在请求时恢复到上下文。
即使保存了历史，也受上下文长度、检索准确性及隐私策略约束。


\subsection{无状态请求、会话历史与 KV Cache 的区别}

对于\textbf{无状态的模型请求接口}，应用把相关系统约束、用户消息、工具结果和历史重新提交，模型据此继续生成。
\localfixture{每轮固定新增 200 Token 的教学假设}
设每轮对话新增 $200$ 个 Token。第 $t$ 轮无删减重传时要提交 $200t$ 个，十轮累计
\[
200\times(1+2+\cdots+10)=200\times55=\boxed{11{,}000}\ \text{个输入 Token},
\]
而新内容只有 $2{,}000$ 个。若只保留最近 $3$ 轮，累计为
$200\times(1+2+3)+7\times600=\boxed{5{,}400}$ 个，代价是更早的信息不再可见。
摘要、检索筛选、截断和提示缓存都在这两端之间取舍，需按任务保留关键证据。
采用服务端会话管理的 API 则由服务保存历史，按该接口约定恢复状态。
\texttt{scripts/agent\_loop.py} 复算这两项累计值。


\textbf{KV Cache} 则是模型执行 Attention 时对已处理 Token 的 Key/Value 缓存，
能减少自回归解码中的重复计算；服务是否跨请求复用缓存取决于具体接口和实现。
应用历史、服务端会话状态与模型 KV Cache，分别保存消息、服务状态与注意力张量。

\subsection{有了资料，为什么仍要逐项核证？}
\phantomsection\label{partq:assistant}

生成文字的流畅程度与事实依据是两个评价维度。
这种没有充分依据甚至编造细节的输出常被称为\textbf{幻觉}。
RAG 可以检索外部材料，帮助模型获取新证据，
检索遗漏、资料过期和生成误读是三类需要分别检查的失败点。
因此，检索结果还需要来源核对、事实检查和权限控制。

\begin{casebox}
\textbf{真实失败案例：逐项核查引用的判例。}
在美国联邦法院的 \emph{Mata v.\ Avianca} 案中，
律师提交的材料引用了不存在的司法判例和捏造的引文；
法院于 2023 年 6 月 22 日在制裁裁定中明确描述了
使用生成式 AI 制造虚假引文且未尽核查责任的问题。
可查阅\href{https://law.justia.com/cases/federal/district-courts/new-york/nysdce/1:2022cv01461/575368/54/}{该案裁定原文（Docket 54）}。
\textbf{失效点}是把生成的出处当成真实证据；
\textbf{正确动作}是打开可核验的原始文件，逐项核对案名、引用和结论。
\end{casebox}

\subsection*{同一报告里的短句与数字，都要找到出处}
公园报告中的“春天花开了”与“Q3 收入 132 百万元”一样，
都是待核验的陈述。模型把它们表示成 Token 并生成解释；
应用把每条陈述对回报告的日期、段落或原表。
这使前面的短句预测与眼前的报告任务接上了同一条链：
\textbf{Token 概率负责生成文字，报告出处负责支撑事实，程序负责核对计算。}

\subsection{RAG 解决“找资料”，工具调用解决“执行动作”}
\phantomsection\label{concept:rag}

沿用上面的 Q1--Q3 比较任务；只有经过授权的原始报告才有资格成为正式数值来源。

我们需要不同类型的能力：
\begin{enumerate}
\item \textbf{定位资料：}搜索相关文件、页面或文档片段；
这是检索层的工作，必要时可使用向量检索和关键词检索。
\item \textbf{提取和计算：}用文件工具读取表格，
用程序检查日期、单位和百分比。
\item \textbf{解释和撰写：}模型结合有来源的数值解释变化，
并按要求输出结果。
\item \textbf{核对：}在输出前检查引用、计算和遗漏，必要时让人复核。
\end{enumerate}
RAG 是将检索结果提供给生成过程的一类方法；
Agent 是组织模型决策与工具动作的系统方式。
一个工作流可以同时用 RAG 和 Agent，也可以两者都不用。


\subsection{［复算］三个二维文档块怎样决定检索结果？}
\phantomsection\label{concept:vector-retrieval}

\localfixture{二维 RAG 检索，独立于三维 Transformer 贯通参数}
先用第~\ref*{intro:02-dot-product}~章的点积代替真实系统中复杂的向量检索：查询
$q=(1,0.5)$；三个文档块（分别来自 Q1、Q2、Q3 报表）的教学向量排成三行：
\[
D=\begin{bmatrix}1&0\\0&1\\0.8&0.8\end{bmatrix}
\quad(3\times2),\qquad
qD^\top
=(1,0.5)
\begin{bmatrix}1&0&0.8\\0&1&0.8\end{bmatrix}
=\boxed{(1,\;0.5,\;1.2)}.
\]
按原始点积降序取 $\operatorname{top}\text{-}2$：
第 3 块（得分 $1.2$）、第 1 块（得分 $1.0$），
\textbf{第 2 块 Q2 被排除}。
\phantomsection\label{concept:recall-at-k}%
用\textbf{必需证据召回率（recall@$k$）}衡量覆盖：前 $k$ 个结果中命中的必需文档数，除以必需文档总数。
本任务需要 Q1、Q2、Q3 三份，
\[
\text{recall@}2=\frac{|\{Q3,Q1\}\cap\{Q1,Q2,Q3\}|}{3}=\frac23\approx\boxed{66.7\%},\qquad
\text{recall@}3=\frac33=100\%.
\]
问题不是排名算法“算错”：\textbf{即使 top-k 完全按定义执行，
固定 $k=2$ 也装不下任务明确需要的三个季度的证据}。
真实系统应先检查每个必要季度是否有可靠来源；
补齐三季度证据后再计算环比。
这里的三行是手设的低维投影，用来核对排序；真实文档向量由
\textbf{文本 Embedding 编码器}生成：分块文本先 Token 化，再通过训练过的网络得到整块表示。
它沿用第~\ref*{intro:20-embeddings}~章“离散文本进入向量”的思路，但检索编码器通常还针对查询与文档匹配训练。

更隐蔽的失败是\textbf{资料找到了，口径却不一致}：若 Q2 原表为 $120$ 百万元，
Q3 附注将 Q2 追溯重述为 $125$ 百万元，那么可比口径的 Q3 环比是
$(132-125)/125=5.6\%$，沿用旧数则得到 $10\%$。
若一张表写“万元”，还须先除以 $100$ 转为“百万元”。
检索分数无法替代这两项检查。

\begin{example}
\noindent\emph{排序完成后，再核对季度与基期}\par
假定原始报告中 Q1、Q2、Q3 的收入依次是 $100,120,132$（百万元）。
若生成时\textbf{误把 Q1 当作 Q2}，便会把 Q3 的环比算成
$(132-100)/100=\boxed{32\%}$；真正的 Q3 环比应该是
$(132-120)/120=\boxed{10\%}$。
检索得到的材料不足时，应报告“缺少 Q2，无法核验环比”，
而不是拿较早季度补位。检索结果还需检查日期、单位和来源，不是排位高就可信。
\end{example}

\noindent{\sffamily\footnotesize\color{blue}\textbf{［复算］}}
运行 \texttt{python3 scripts/rag\_demo.py} 可核对向量形状、三项分数、top-k 排序、recall@$k$ 及两种增长率。


\subsection{幻觉与校准：回答流畅，依据够吗？}
\phantomsection\label{concept:hallucination-calibration}

将“Q2 收入 120 百万元”写得流畅，和从原表找到这一数字，是两项不同的能力。
\textbf{幻觉}是输出缺乏依据或与事实不符的内容；
本章把回答拆成可核对的主张：季度、收入、单位、原表位置。
找不到证据的主张应补检索、标为待核验，或在交付时省略。

\textbf{校准}检查置信分数是否对应真实正确频率。
假设系统在独立保留集上给十条收入判断都打了 $0.8$ 的正确置信分数，
最后只有六条正确：平均置信度为 $0.8$，实际正确率为 $6/10=0.6$，
这一组过度自信 $0.2$。再收集其他分数段，比较每组置信度与正确率，
就能画出可靠性图。
分组、样本量、评分来源及任务分布都应随结果记录。

\begin{boundarybox}
这里的置信分数针对“这项主张是否正确”，要用保留集验证；
下一 Token 的 Softmax 概率和模型口头说出的“80\%”，都不能直接当成事实正确率。
改进平均校准也仍需逐条核验关键主张。
\end{boundarybox}
分类校准的基础定义见\href{https://proceedings.mlr.press/v70/guo17a.html}{Guo 等（2017）}；
应用到生成任务时，先定义主张与判定标准，再估计其正确频率。

\item \textbf{证据：}要比较 Q1--Q3，Top-2 只返回 Q3 和 Q1。先不计算增长率，指出缺哪份证据，以及系统下一步该怎样办。\chapterinlinehint{把任务所需季度与已返回季度做集合对照。}
\item \textbf{手算：}任务需要 Q1--Q4 四份报表，Top-3 返回 Q4、Q2、去年 Q4（不在任务范围内）。求必需证据的 recall@3；若改取 Top-5 后又命中 Q1、Q3，recall@5 是多少？\chapterinlinehint{先写出必需集合，再数前 $k$ 个结果中命中的必需文档。}

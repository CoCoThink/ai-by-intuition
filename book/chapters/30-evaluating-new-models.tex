\section{面对新模型与新缩写，怎么判断它值不值得学？}
\label{intro:23e-tech-judgement}



我们已从语言模型走到系统工具、部署，再回看 RoPE、MoE、GQA 等架构。
技术名称不断变化，但读者不必为了追赶每个缩写而重新背一遍名词表。
更重要的是拿到一个新技术时，能独立判断\textbf{它解决了哪个瓶颈，
用什么证据证明，付出了什么代价，以及哪些条件下会失效}。

\subsection{先把“改进”分到四层，而不是混在一起}

\begin{enumerate}
\item \textbf{表示层：}Tokenizer、Embedding、位置表示如何编码输入？
先追踪文本怎样进入网络，再测量表示改变带来的收益。
\item \textbf{模型计算层：}Attention、FFN、MoE、归一化与缓存改变什么？
区分训练 FLOPs、解码延迟、KV 内存和总参数量。
\item \textbf{训练与反馈层／推理策略层：}改动修改了权重，还是在固定权重下多花计算？
两层的区分见\hyperref[sec:training-inference-roles]{后训练章分工表}；这里追问数据、奖励与评测目标是否一致。
\item \textbf{系统层：}RAG、工具、MCP、Workflow、Agent/A2A 是怎样连接
资料与授权动作的？安全责任归谁？
\end{enumerate}
例如“模型接入新的报表搜索工具”，改变的是\textbf{系统可获得的证据}；
神经网络的参数与宽度没有因此变化。

\subsection{Scaling Laws：更多参数一定更聪明吗？}
\label{sec:scaling-compute-budget}

假设训练算力已经固定：是把模型做大，还是让较小的模型多读一些数据？
先把这笔账算出来。用 $N$ 表示参数个数，$D$ 表示训练中累计处理的 Token 数
（同一 Token 重复训练也重复计数），$C$ 表示训练所需的浮点运算总量，单位是 FLOPs。
对稠密 Transformer，常用的粗略预算是
\[
\boxed{C\approx6ND.}
\]
系数 $6$ 来自每个参数、每个 Token 约 $2$ 次前向运算与约 $4$ 次反向运算。
它概括主要矩阵计算；上下文长度、Embedding 的计数口径与实现会影响误差，
不能直接换算成实际训练时长。

把前文 GPT-2 small 约 $1.244$ 亿参数取整到 $N=1.25\times10^8$，
假设训练预算为 $C=1.875\times10^{18}$ FLOPs，能够处理多少 Token？
\[
\begin{aligned}
D&\approx\frac{C}{6N}
=\frac{1.875\times10^{18}}{6\times1.25\times10^8}\\
&=2.5\times10^9=\boxed{25\text{ 亿 Token}}.
\end{aligned}
\]
预算不变时，若参数翻倍为 $2.5\times10^8$，训练 Token 就只能减半为 $12.5$ 亿。
这两份方案的乘积 $ND$ 相同，但算力相同并不意味着损失相同：哪种分配更好，还要用实验判断。

\textbf{Scaling Laws（缩放规律）}研究的正是参数、训练数据、算力与验证损失之间的经验关系。
Kaplan 等（2020）的\href{https://arxiv.org/abs/2001.08361}{早期研究}讨论了这些趋势；
Hoffmann 等（2022）的\href{https://arxiv.org/abs/2203.15556}{Chinchilla 研究}进一步比较固定训练算力下的分配。
论文中的 Chinchilla 用 $700$ 亿参数训练了 $1.4$ 万亿 Token，比例为
\[
\frac{D}{N}=\frac{1.4\times10^{12}}{7\times10^{10}}=20.
\]
把 $D\approx20N$ 用作一个简化预算起点，本例的 $25$ 亿恰为参数量的 $20$ 倍。
若参数和 Token 都翻倍，代入 $6ND$，所需算力就变成原来的 $4$ 倍。

这里是借 GPT-2 量级做的玩具估算，并非 GPT-2 实际训练记录；
$20$ 倍也不是通用最优配方。真实预算还要评估数据质量、上下文长度与部署成本。

\subsection{Bitter Lesson：计算与通用方法为何常被重视？}

Richard Sutton 在
\href{http://www.incompleteideas.net/IncIdeas/BitterLesson.html}{The Bitter Lesson}
中主张，长期来看，能够借助增长的计算规模进行学习或搜索的通用方法，
往往比大量手写领域规则更有扩展性。
这项\textbf{经验观点}鼓励我们优先寻找能随计算扩展的办法；
具体应用中的安全规则和固定工作流仍应明确编写。
\hyperref[part:learning]{开篇的学习与训练部分}问“为什么规则难以写尽”，在这里得到了一次回响：
\textbf{让系统学会一般模式，与让应用遵守明确规则，并不矛盾。}

常与此并提的\textbf{莫拉维克悖论（Moravec's paradox）}则指出：
棋类、符号运算有明确的输入与计分，较早被计算机处理；
人类不假思索的感知与身体操作，反而要应对噪声、遮挡和环境变化。
评估一项技术时，因此要追问\textbf{训练分布以外，哪些输入条件会失败}
（\href{https://en.wikipedia.org/wiki/Moravec%27s_paradox}{历史背景概述}）。

\subsection{“架构创新空间正在收窄”是可检验的争议观点}

一种立场认为：大规模预训练、Transformer 的成熟工程栈、
标准化评测和推理服务的规模效应，
使很多任务上\textbf{沿既有架构改进数据、训练和系统效率}
更容易获得可复现收益。
支持这项判断的证据应是：成熟结构在公开对照实验中持续提供更高的单位成本收益。

另一种立场指出：序列建模还包括状态空间、线性状态与混合路线。
例如\href{https://arxiv.org/abs/2312.00752}{Mamba}
等状态空间路线、
\href{https://arxiv.org/abs/2412.06464}{Gated DeltaNet}
等状态更新结构以及混合层，
探索了长序列信息流和运行成本的不同权衡。
它们分别尝试压缩状态、保留随机访问，或在两种信息通路之间分配计算。

\subsection{拿到宣传语，先做一次拆解}

假设听到一句：“新注意力让上下文扩大十倍，速度提升十倍，
因此所有业务的答案都会更准确。”
先要求补齐缺失的证据：
\begin{itemize}
\item \textbf{比较对象：}与哪一个基线、哪一种实现、哪一个硬件平台比较？
\item \textbf{指标定义：}更快指首 Token 延迟、吞吐还是总运行时间？
上下文变长不自动等于能准确找到远处证据。
\item \textbf{质量代价：}长程检索、普通对话、代码等任务是否都测过？
有没有关键回归？
\item \textbf{实验条件：}输入长度、并发数、精度、缓存策略和训练量是否相同？
\item \textbf{应用边界：}引用核查、工具权限、失败处理有没有另外验证？
\end{itemize}
不同技术的收益落在不同指标上：GQA 主要减少解码时的 KV 缓存显存，
MoE 在专家宽度与每 Token 选取的专家数固定时，可增加总专家参数而保持相近的专家计算量，
实际耗时还包括路由、负载分配与通信，
固定 Workflow 主要减少人工操作；\textbf{三者应按各自的瓶颈与指标比较}。


\subsection{从交叉熵到困惑度：评测先要明确量尺}
\phantomsection\label{concept:perplexity}

语言模型常用\textbf{困惑度（Perplexity, PPL）}概括
保留测试集上的平均下一 Token 交叉熵。
如果交叉熵按自然对数计算，每个 Token 的平均损失为 $L$，
则 $\mathrm{PPL}=e^L$。

先固定词表只有五项。若每项概率都是 $1/5$，每道题的损失为 $\ln5$，
困惑度为 $e^{\ln5}=5$。
再设模型在每道题上只给正确 Token $1/10$ 的概率，余下四项合计得到 $9/10$。
此时平均损失为 $\ln10$，困惑度为 $10$，\textbf{词表却仍只有五项}。
困惑度衡量真实目标获得的概率大小，数值可以超过词表大小。

\begin{example}[breakable=false]
\noindent\emph{沿用三位置前向实验的损失}\par
第~\ref*{intro:22c-language-training}~章训练前的三维贯通例，在该训练样本上三个预测位置的平均交叉熵为 $L=1.798430$，
因此
\[
\mathrm{PPL}=e^{1.798430}\approx 6.04.
\]
这里的 $6.04$ 与前面的 $5$、$10$ 一样，来自正确目标概率的负对数平均。
它与“最大概率的类别答对了几道”衡量不同事情。
本例演示计算方法；正式报告泛化表现时，应在独立保留的数据上计分。
\end{example}

\textbf{评测（Evaluation）}至少区分四类量尺：
语言概率可看交叉熵和 PPL；有标准答案的任务可看准确率、
通过率或 exact match；RAG 系统要检查\textbf{证据覆盖与引用准确率}；
Agent 还需记录工具成功率、越权率、延迟、成本和失败恢复。
跨 Tokenizer 比较 PPL 时，须先统一切分与计分口径。

\subsection{为什么 Benchmark 高分仍需要复核？}
\phantomsection\label{concept:evaluation-contamination-benchmark}

\textbf{Benchmark（基准测试）}必须说明数据构造、题目来源、
评分脚本、样本量与置信区间。
榜单高分还要排除\textbf{评测污染（Benchmark Contamination）}：
它的定义与去重、按组切分的做法见\hyperref[concept:evaluation-contamination]{训练数据工程一节}；
读榜时追问测试题是否进入过训练、微调、检索库或反复调参，并优先看时间隔离的新题复测。

\textbf{数据偏见与模型偏见}同样需要评估：
训练资料是否遗漏特定语言、地区或群体？
同一服务在不同用户场景下是否出现系统性的错误差异？
标注规则由谁确定，错误由谁承担？
同时评估隐私数据泄露、未经授权的操作与提示注入，
应同时报告分组指标、平均分与真实事故分析。
人工审核可提供质性证据，但需记录审核者分歧和判定规则。

\subsection{LLM 评审：让裁判也接受复核}
\phantomsection\label{concept:llm-judge}

开放式回答没有唯一字符串答案时，可让另一个 LLM 按评分表比较候选回答。
先写明评分维度，例如事实正确、证据充分、遵守任务与表达清楚；
把参考证据和候选回答分别放入数据字段，再输出分项分数及理由。
涉及金额的计算仍交给程序核对。

\textbf{一个最小复核：}同一对回答先按 A/B 排列评分，再交换为 B/A。
若赢家随位置翻转，标记为裁判不稳定；抽取人工复核集，统计与人工判断的一致率，
并保留裁判模型版本、评分 Prompt、采样设置和原始判词。
长回答、特定风格与同源模型都可能影响偏好，因此质量结论要和评分协议一起报告。
这些偏差在\href{https://arxiv.org/abs/2306.05685}{Zheng 等（2023）的 LLM-as-a-Judge 研究}中有实证讨论。

\textbf{每次选型都留下五项记录：}旧方法的瓶颈，新方法的输入与输出，
可复算证据，被转移的成本或风险，以及退回简单方法的条件。

\begin{boundarybox}[title={适用条件：本章比较共用的一把尺}]
固定任务、数据隔离、训练预算、Tokenizer、硬件与服务负载；同时报告质量、首 Token 延迟、吞吐和内存。
缩放趋势与研究观点各有实验范围。证据缺项时保留该项为待测，不把局部收益外推到所有任务。
\end{boundarybox}

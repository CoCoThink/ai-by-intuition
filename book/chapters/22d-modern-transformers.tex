\section{现代 Transformer 为什么看起来越来越不像原版？}
\label{intro:22d-modern-transformers}

\begin{idea}
\noindent\emph{不是背新缩写，而是问“改动想解决哪种成本？”}\par

刚刚学会逐词生成，就遇到一个实际问题：每多生成一个 Token，历史 K/V 缓存可能变得更大。
这就是 \conceptlink{kv-cache}{KV Cache} 相关架构改进的动机。
此外，长序列计算、归一化的稳定性和 FFN 的成本，也会让我们重新考虑原始模块。
因此，本章的每个新缩写都应该对应\textbf{一个具体约束或代价}，而不是意味着原来的 Transformer 已经“失效”。
一些改动帮助模型处理位置信息，一些改动帮助控制深层网络的数值尺度，
有的降低缓存或计算成本，还有的让总参数变多却不必每次全部计算。
本章围绕五个\textbf{稳定问题}整理现代架构，不按品牌或年份排列“技术排行榜”。
\end{idea}

\subsection{问题一：位置信息怎么进入 Attention？}
\phantomsection\label{concept:rope}

经典 Transformer 可以把位置向量 $P$ 加在 Token 嵌入上：
$X_0=X_{\rm token}+P$。另一些模型使用\textbf{旋转位置表示（RoPE）}：
不是简单地在 Token 向量上增加某组固定数字，
而是对 Query 和 Key 的部分二维分量施加\textbf{与位置相关的旋转}。

先用\textbf{两个整数位置}和二维旋转矩阵算一遍：
\[
R(\phi)=
\begin{bmatrix}\cos\phi&-\sin\phi\\
\sin\phi&\cos\phi\end{bmatrix},
\quad
R(\phi)\begin{bmatrix}1\\0\end{bmatrix}
=\begin{bmatrix}\cos\phi\\\sin\phi\end{bmatrix}.
\]
假如 Query 位置是 $m$，Key 位置是 $n$，分别旋转
$m\theta$ 和 $n\theta$，则
\begin{equation}
(R(m\theta)\vect q)^\top (R(n\theta)\vect k)
=\vect q^\top R((n-m)\theta)\vect k.
\label{eq:rope-relative}
\end{equation}
\textbf{右边出现了相对位置差 $n-m$。}
这让注意力分数有机会利用两位置之间的距离和方向。
高维 RoPE 会对多个分量对使用不同角频率，
并不是每个 Token 只绕一个二维圆周旋转。
长上下文扩展仍可能需要额外设计与实测，不能从这个恒等式直接保证无限外推。

\begin{example}
\noindent\emph{真实旋转一次，而不只背恒等式}\par

取 $\vect q^\top=\vect k^\top=(1,0)$，
Query 位于 $m=0$，Key 位于 $n=1$，
选择角频率 $\theta=\pi/2$。
将两个向量以列形式代入旋转定义，
得到
\[
R(0)\begin{bmatrix}1\\0\end{bmatrix}
=\begin{bmatrix}1\\0\end{bmatrix},
\qquad
R(\pi/2)\begin{bmatrix}1\\0\end{bmatrix}
=\begin{bmatrix}0\\1\end{bmatrix}.
\]
两者点积等于 $0$。
若 $m=n=0$，两个向量都为 $(1,0)$，
点积为 $1$。因此即使内容特征不变，
相对位置也能改变 Q/K 分数。
\end{example}

\subsection{问题二：归一化为什么从 LayerNorm 变成 RMSNorm？}

\textbf{LayerNorm} 通常先减去特征均值，再按方差缩放（还可以学习仿射参数）。
\textbf{RMSNorm} 侧重通过均方根控制大小，不执行相同的均值中心化。

只看一条二维向量 $\vect x=(3,4)$：
\[
\operatorname{RMS}(\vect x)
=\sqrt{\frac{3^2+4^2}{2}}=\sqrt{12.5}.
\]
忽略可学习缩放参数与小正数 $\varepsilon$，
RMS 归一化后的数字约为 $(0.849,1.131)$。
这个例子并不意味着每个模型的实际输出都如此；
真实层还可能使用 $\varepsilon$ 和可学习的增益。

\textbf{Pre-Norm 与 Post-Norm} 表示归一化放在子层之前或之后，
会改变残差路径与训练行为。不能仅凭名称断言一种实现
在所有模型中总比另一种更强。

\subsection{问题三：FFN 除了 ReLU 还能做什么？}
\phantomsection\label{concept:moe}

常规 \conceptlink{ffn}{FFN} 使用两次矩阵投影夹一个激活函数。
现代网络还常使用\textbf{门控 FFN}，例如 SwiGLU 形式：
\begin{equation}
\operatorname{FFN}(\vect x)
=\left[
\operatorname{SiLU}(\vect x^\top W_g)
\odot(\vect x^\top W_u)\right]W_{\rm down},
\label{eq:swiglu-illustration}
\end{equation}
其中 $\odot$ 是\textbf{对应位置逐元素相乘}，
$\operatorname{SiLU}(z)=z/(1+e^{-z})$；
真实实现通常还处理偏置、并行化及其他配置。
两个分支分别计算“门”和“内容”，然后逐元素组合。

还有一种\textbf{混合专家（MoE）}思路：
不是让每个 Token 都经过同一个巨大的 FFN，
而是使用\textbf{路由器}挑选部分专家处理它。

一个最简单的路由示例：三个专家的得分是 $(2,1,0)$，
如果只选择最高的一个专家，本次仅计算专家 1，
其他专家并未被本次 Token 调用。
如果选择 Top-2，就可能计算两个专家并按路由权重组合。
实际系统还需要处理负载均衡、通信与容量限制。

\begin{warningbox}
稀疏激活并不等于无成本。MoE 可以拥有很大的\emph{总参数量}，
而每个 Token 只激活其中一部分专家；但设备仍需存储或调度权重，
还存在路由、通信和内存负担。Dense（稠密）与 MoE 并非简单的谁取代谁。
\end{warningbox}

\subsection{问题四：多头 Attention 为什么开始共享 K/V？}
\phantomsection\label{concept:gqa}

标准 \conceptlink{multihead}{多头注意力}（MHA）可以为每个 Query 头保存自己的 Key/Value 头。
在自回归生成中，过去 Token 的 K/V 需要反复使用，于是产生 KV Cache。
\textbf{MQA} 让多个 Query 头共享一组 K/V；
\textbf{GQA} 让每组 Query 头共享一组 K/V，
是在“完全独立”和“全部共享”之间的一种折中。

为了比较缓存的\textbf{理论元素个数}，假设单层：
上下文长度 $T=100$，每头维度 $d_h=8$，
有 8 个 Query 头。如果 MHA 有 8 个 K/V 头：
\[
\underbrace{2}_{K,V}\times
\underbrace{100}_{T}\times
\underbrace{8}_{h_{kv}}\times
\underbrace{8}_{d_h}
=\boxed{12{,}800\ \text{个数}}.
\]
若采用 2 个 K/V 头的 GQA：
\[
2\times100\times2\times8=\boxed{3{,}200\ \text{个数}}.
\]
在这个简化例子里，缓存元素数缩小为原来的四分之一。
要换算成实际字节，还必须乘以每个元素占用的字节数、
模型层数和批量大小，并考虑缓存布局、分配及实现开销。

\textbf{MLA} 等低秩潜在表示技术则尝试使用另一种缓存压缩方案，
与简单减少 K/V 头数的设计思路不同；不应把所有缩写视为同一种运算。

\subsection{问题五：长上下文能否不两两比较全部 Token？}

对长度为 $T$ 的普通全量 Attention，分数矩阵有 $T^2$ 个位置；
如果 $T$ 从 $100$ 增到 $200$，潜在分数位置从 $10{,}000$
变成 $40{,}000$。这解释了长序列计算面临的压力。

\small

\begin{tabularx}{\linewidth}{@{}p{25mm}X@{}}
\toprule

复杂度判断必须写清对象。有的改进降低训练的分数矩阵开销，
有的主要节约解码时的 KV Cache，有的减少单 Token 计算，
并不能简单把它们都称为“Attention 变成线性复杂度”。

\begin{conclusion}
现代 Transformer 的变化不是“把经典组件全部宣判过时”：
每个变体都是在某些约束下重新选择位置、数值尺度、
参数使用方式和上下文访问方式。
判断一项技术，先问它解决了什么已知问题，在哪种计算或数据条件下有收益，付出了什么代价。
架构已经改进，不代表模型就会自动更好地遵循指令或判定事实。
下一章把问题从\textbf{计算成本}转向\textbf{模型的回答行为}：预训练后的模型怎样进一步适应真实对话？
\end{conclusion}

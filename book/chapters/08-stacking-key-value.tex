\section{把 Key 和 Value 堆成矩阵：中间并没有魔法}

我们已经知道每条记忆都有一个 Key 和一个 Value。但初学者最容易卡住的恰恰是
\[
\sum_i\vect{v}_i\,\sigma(\vect{k}_i^\top\vect{x})
\quad\longrightarrow\quad
V^\top\sigma(K\vect{x}).
\]
\textbf{为什么能堆？为什么 ReLU 能放在两个矩阵乘法之间？}这一节完全拆开手算。

\subsection{两条记忆，各用两个数字表示}

先约定两条 Key--Value 关系：
\begin{align*}
\vect{k}_1&=\begin{bmatrix}1\\0\end{bmatrix},
& \vect{v}_1&=\begin{bmatrix}2\\1\end{bmatrix},\\
\vect{k}_2&=\begin{bmatrix}0.6\\0.8\end{bmatrix},
& \vect{v}_2&=\begin{bmatrix}0\\3\end{bmatrix}.
\end{align*}
给出查询：
\[
\vect{x}=\begin{bmatrix}1\\-1\end{bmatrix}.
\]
\textbf{不使用矩阵}时，分别计算两个匹配分数：
\begin{align*}
s_1&=\vect{k}_1^\top\vect{x}=1\cdot1+0\cdot(-1)=1,\\
s_2&=\vect{k}_2^\top\vect{x}=0.6\cdot1+0.8\cdot(-1)=-0.2.
\end{align*}
所以两个 Key 的匹配程度为 $1$ 和 $-0.2$。现在我们只想把\textbf{这两次点积合并计算}。

\subsection{第一个矩阵：每行是一条 Key}

把两条 Key \textbf{横放成两行}：
\begin{equation}
K=\begin{bmatrix}
  1 & 0\\
  0.6 & 0.8
\end{bmatrix}.
\end{equation}
矩阵乘列向量的规则是：\textbf{左边每一行，与右边那一列分别点积}。

\begin{example}[title={用一行乘一列，亲手算两次}]
\begin{align*}
K\vect{x}
&=\begin{bmatrix}1&0\\0.6&0.8\end{bmatrix}
  \begin{bmatrix}1\\-1\end{bmatrix}\\
&=\begin{bmatrix}
1\cdot1+0\cdot(-1)\\
0.6\cdot1+0.8\cdot(-1)
\end{bmatrix}
=\boxed{\begin{bmatrix}1\\-0.2\end{bmatrix}}.
\end{align*}
第一行的结果恰好是 $s_1$，第二行的结果恰好是 $s_2$。
\end{example}

因此，下面两个表达式\textbf{一模一样}：
\[
K\vect{x}
=
\begin{bmatrix}\vect{k}_1^\top\vect{x}\\\vect{k}_2^\top\vect{x}\end{bmatrix}
=
\begin{bmatrix}s_1\\s_2\end{bmatrix}.
\]
堆成矩阵并没有添加新的数学假设，只是用一种方便批量计算的记法表示多次点积。

\subsection{ReLU 不乘矩阵：它逐个处理分数}

矩阵乘法算完后，结果已经是一个普通的两维向量：
\[
\vect{s}=K\vect{x}=\begin{bmatrix}1\\-0.2\end{bmatrix}.
\]
激活函数 $\relu(t)=\max(0,t)$ 只处理\textbf{一个数}。当输入是向量时，约定它\textbf{逐元素处理}：
\begin{equation}
\relu(\vect{s})
=\begin{bmatrix}\relu(1)\\\relu(-0.2)\end{bmatrix}
=\boxed{\begin{bmatrix}1\\0\end{bmatrix}}.
\end{equation}
这一步不是矩阵乘法，也不是对 $K$ 的每个元素先做 ReLU。\textbf{它处理的是 $K\vect{x}$ 计算出的两项匹配分数。}

记新的分数向量为
\[
\vect{a}=\relu(K\vect{x})=\begin{bmatrix}1\\0\end{bmatrix}.
\]
直觉是：第一条记忆保留权重 $1$；第二条记忆被压到 $0$。

\subsection{三个重要符号：记忆数量与向量维度}

后面会反复出现 $M$、$d_k$ 和 $d_v$。它们分别回答三个不同的问题：

\begin{center}
\small
\renewcommand{\arraystretch}{1.35}
\begin{tabularx}{\linewidth}{@{}p{18mm}X p{40mm}@{}}
\toprule
符号 & 意思 & 一个例子\\
\midrule
$M$ & 有多少\textbf{条 Key--Value 记忆} & 2 条，则 $M=2$\\
$d_k$ & 每条\textbf{Key 含多少个数字}；Query 也需要有同样的维度 & $(1,0)$ 是二维，$d_k=2$\\
$d_v$ & 每条\textbf{Value 含多少个数字}；输出向量通常也有这个维度 & $(2,1,0)$ 是三维，$d_v=3$\\
\bottomrule
\end{tabularx}
\end{center}

这里的 $d$ 是英文 \emph{dimension}（维度）的缩写；下标 $k$、$v$ 分别表示 Key、Value。\textbf{Key 和 Value 的维度不一定相同。}

例如两条记忆的 Key 都有 2 个数字，而 Value 都有 3 个数字：
\[
\vect k_1=(1,0)^\top,\quad \vect k_2=(0,1)^\top;
\qquad
\vect v_1=(2,1,0)^\top,\quad \vect v_2=(0,3,4)^\top.
\]
此时 $M=2$、$d_k=2$、$d_v=3$，因而
\[
\underbrace{K}_{2\times2}
=\begin{bmatrix}1&0\\0&1\end{bmatrix},
\qquad
\underbrace{V}_{2\times3}
=\begin{bmatrix}2&1&0\\0&3&4\end{bmatrix}.
\]
这就是为什么不能把 $M$ 与 $d_k$ 混为一谈：前者\textbf{数记忆的条数}，后者\textbf{数每条 Key 有几个数字}。

\subsection{为什么 Key 是行，而 Value 从列中读出？}

这不是 AI 特有的规则，而是\textbf{我们选择如何摆放数字}。在本卷，输入 Query 是一个列向量 $\vect x$。

如果看到 $K$ 和 $K^\top$ 就容易迷失方向，可以先回看\hyperref[sec:layout-matrix-card]{矩阵乘法章的行列对照图}；进入 Self-Attention 后，再看\hyperref[sec:key-layout-card]{Key 与 Value 的完整并排图}。

\textbf{Key 的任务是和 Query 做点积。}为了让一次乘法得到全部 $M$ 条 Key 的分数，就把 Key 依次放成行：
\[
\underbrace{K}_{M\times d_k}
=\begin{bmatrix}
\vect k_1^\top\\\vdots\\\vect k_M^\top
\end{bmatrix},
\quad
K\vect x=
\begin{bmatrix}\vect k_1^\top\vect x\\\vdots\\\vect k_M^\top\vect x\end{bmatrix}.
\]

\textbf{Value 的任务是被匹配分数加权相加。}如果权重向量是
$\vect a=(a_1,\ldots,a_M)^\top$，希望得到：
\[
\vect y=a_1\vect v_1+\cdots+a_M\vect v_M.
\]
为了把它写成一次矩阵乘法，最方便的是把 Value \textbf{按列}放：
\[
\underbrace{\widetilde V}_{d_v\times M}
=\begin{bmatrix}\vect v_1&\cdots&\vect v_M\end{bmatrix},
\quad
\boxed{\vect y=\widetilde V\vect a.}
\]

但如果最初约定把全部 Value \textbf{按行}存成一个叫 $V$ 的矩阵：
\[
V=\begin{bmatrix}\vect v_1^\top\\\vdots\\\vect v_M^\top\end{bmatrix}
\in\mathbb R^{M\times d_v},
\]
那么按列排放的矩阵正好就是 $V^\top$：
\begin{equation}
\boxed{\widetilde V=V^\top,\qquad \vect y=V^\top\vect a.}
\label{eq:two-value-orientations}
\end{equation}

\begin{idea}
\textbf{最关键的不是记住转置符号，而是知道这一步要做什么。}
$K\vect x$ 用逐行点积计算\textbf{匹配分数}；$V^\top\vect a$ 用按列加权求和形成\textbf{输出}。
也可以从一开始就叫按列矩阵 $\widetilde V$，那根本不必写转置。
\end{idea}

\subsection{第二个矩阵：每列是一条 Value}

我们希望的输出是\textbf{按照激活分数，将 Value 加权求和}：
\begin{equation}
\vect{y}=a_1\vect{v}_1+a_2\vect{v}_2.
\end{equation}
现在把两个 Value 排成\textbf{两列}：
\begin{equation}
V^\top=
\begin{bmatrix}
\vect{v}_1&\vect{v}_2
\end{bmatrix}
=
\begin{bmatrix}
2&0\\
1&3
\end{bmatrix}.
\end{equation}
为什么是列？因为矩阵乘列向量也有等价的解释：\textbf{用右侧的每个数字，对左侧相应列做加权求和}。

\begin{example}[title={矩阵乘向量 = 按列加权求和}]
\begin{align*}
V^\top\vect{a}
&=\begin{bmatrix}2&0\\1&3\end{bmatrix}
  \begin{bmatrix}1\\0\end{bmatrix}\\
&=\begin{bmatrix}2\cdot1+0\cdot0\\1\cdot1+3\cdot0\end{bmatrix}\\
&=1\begin{bmatrix}2\\1\end{bmatrix}
 +0\begin{bmatrix}0\\3\end{bmatrix}
=\boxed{\begin{bmatrix}2\\1\end{bmatrix}}.
\end{align*}
我们取回了第一条 Value，第二条因为激活为 $0$ 而没有参与。
\end{example}

\subsection{整个过程连在一起}

现在把刚才三个独立步骤写在同一张纸上：
\begin{align}
\text{匹配：}\quad
K\vect{x}
&=\begin{bmatrix}1\\-0.2\end{bmatrix},\\
\text{筛选：}\quad
\relu(K\vect{x})
&=\begin{bmatrix}1\\0\end{bmatrix},\\
\text{读出：}\quad
V^\top\relu(K\vect{x})
&=\begin{bmatrix}2\\1\end{bmatrix}.
\end{align}

\node[n,below=of c] (d) {$V^\top\relu(K\vect{x})=(2,1)^\top$：按列混合 Value};

\begin{conclusion}
一定要分开理解：\textbf{$K\vect{x}$ 是批量点积；ReLU 是逐元素函数；$V^\top\vect{a}$ 是按列加权求和。}每一步的输出都恰好是下一步能够接收的输入。
\end{conclusion}

\subsection{维度检查：为什么它们可以相乘？}

前面两条记忆、二维 Key、二维 Value，所以恰好都是 $2\times2$ 方阵。但真实情况并不需要是方阵。

沿用前文：$M$ 是记忆条数，$d_k$ 是 Key 的维度，$d_v$ 是 Value 的维度。于是：
\[
\underbrace{K}_{M\times d_k}
\underbrace{\vect{x}}_{d_k\times1}
=\underbrace{\vect{s}}_{M\times1},
\qquad
\underbrace{V^\top}_{d_v\times M}
\underbrace{\sigma(\vect{s})}_{M\times1}
=\underbrace{\vect{y}}_{d_v\times1}.
\]
从矩阵大小看，\textbf{内侧维度必须相等}：第一个乘法的 $d_k$ 对得上；第二个乘法的 $M$ 对得上。

例如 100 条记忆，Key 维度 64，Value 维度 32：
\[
(100\times64)(64\times1)=(100\times1),
\]
\[
(32\times100)(100\times1)=(32\times1).
\]
这里并没有神秘的“特殊神经网络矩阵乘法”，始终是普通的线性代数。

\subsection{这和外积求和到底是什么关系？}

如果\textbf{不加 ReLU}，之前的外积求和能合并：
\begin{equation}
\underbrace{V^\top K}_{W}
=
\begin{bmatrix}\vect{v}_1&\vect{v}_2\end{bmatrix}
\begin{bmatrix}\vect{k}_1^\top\\\vect{k}_2^\top\end{bmatrix}
=
\vect{v}_1\vect{k}_1^\top+\vect{v}_2\vect{k}_2^\top.
\end{equation}
所以线性召回可以写成：
\[
W\vect{x}=(V^\top K)\vect{x}=V^\top(K\vect{x}).
\]
\textbf{一旦把 ReLU 放在中间，通常就不能合并成一个固定的 $W$。}以本节数字为例：
\begin{align*}
V^\top K\vect{x}
&=1\vect{v}_1-0.2\vect{v}_2
=\begin{bmatrix}2\\0.4\end{bmatrix},\\
V^\top\relu(K\vect{x})
&=1\vect{v}_1+0\vect{v}_2
=\begin{bmatrix}2\\1\end{bmatrix}.
\end{align*}
前者保留了负匹配；后者把它滤掉了。这就是激活函数引入\textbf{非线性}的实际效果。

\begin{warningbox}
\textbf{行列约定：}这里规定 $K$ 与 $V$ 的每一\textbf{行}是一条 Key、Value，所以公式使用 $V^\top\sigma(K\vect{x})$。有些教材直接把 Value 放在\textbf{列}中，记为 $\widetilde V$，便会写成 $\widetilde V\sigma(K\vect{x})$。只是摆放约定不同，内容相同。标准 Transformer 的批量 $Q,K,V$ 通常按 Token 放在行上。
\end{warningbox}

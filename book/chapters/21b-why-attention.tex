\section{Attention 是什么？让一个词直接读取其他位置}
\phantomsection\label{concept:attention}
\label{intro:21b-why-attention}

\begin{idea}[title={先给 Attention 一个能听懂的定义}]
\textbf{Attention（注意力）是一种按相关性读取信息的方法：}
当前这个位置先对\textbf{可读取的每个位置}算一个匹配分数，
再把这些分数变成\textbf{权重}，
最后把各位置提供的信息按权重\textbf{加起来}。

它最核心的三个动作就是
\textbf{比较 $\to$ 分配权重 $\to$ 加权读取}。
这不是说模型像人一样拥有注意力意识，
而是一个具体的可训练数学运算。
\end{idea}

\subsection{为什么 RNN 已经能传信息，还需要另一个办法？}

上一章的 \conceptlink{rnn}{RNN} 让模型按顺序读：
\[
\underbrace{\text{春天}}_{\text{第 1 词}}
\ \to\
\underbrace{\text{花}}_{\text{第 2 词}}
\ \to\
\underbrace{\text{开了}}_{\text{第 3 词}}.
\]
RNN 的第 3 步能读到\textbf{上一份状态} $h_2$，
但如果想重点利用第 1 个词的信息，
它必须依赖这份状态此前是否保留了相关内容。

现在试想另一种设计：当我们读到第三个词“开了”时，
\textbf{不必只能通过 $h_2$ 间接获得过去的信息；
让第三个位置直接查看前三个位置，各自决定读多少。}

\input{figures/attention-rnn-bridge}
\textbf{这几根箭头的意思：}在这个简化例子中，
位置 3 可以直接从位置 1、2、3 读取信息，
不同箭头并不要求权重相等。
我们还没有说权重具体由什么决定，下面就设计这件事。

\subsection{先不提 QKV：一次“读取”到底要算什么？}

如果前面有三个可以读取的位置，
每个位置都保存一条\textbf{内容向量}。
为了便于手算，假设三条内容分别是
\[
\vect c_1=\begin{bmatrix}1\\0\end{bmatrix},\quad
\vect c_2=\begin{bmatrix}0\\1\end{bmatrix},\quad
\vect c_3=\begin{bmatrix}1\\1\end{bmatrix}.
\]
最简单的方法是把它们\textbf{平均}：
\[
\vect y_{\rm avg}
=\frac13(\vect c_1+\vect c_2+\vect c_3)
=\begin{bmatrix}2/3\\2/3\end{bmatrix}.
\]
但无论当前位置想查找什么，只要内容不变，
平均结果就不变。\textbf{它没有考虑当前的查找需要。}

不妨先给三条内容分配权重 $a_1,a_2,a_3$，
且规定权重非负、总和为 $1$：
\begin{equation}
\boxed{\vect y=a_1\vect c_1+a_2\vect c_2+a_3\vect c_3,\qquad
a_i\ge0,\quad \sum_{i=1}^3 a_i=1.}
\label{eq:attention-design-goal}
\end{equation}
刚才的平均，只是 $a_1=a_2=a_3=1/3$ 的特例。
真正缺少的东西是：
\textbf{这些权重该由谁决定？不同位置该读不同内容时怎么办？}

于是我们把任务拆成两件事：
\begin{enumerate}
\item \textbf{先算“读谁、读多少”。}
当前位置有一个\textbf{查找需求}，每个候选位置需要提供
能与这个需求比较的\textbf{匹配特征}。
\item \textbf{再算“读到什么”。}
一旦知道读取比例，就按这些比例组合各位置保存的内容。
\end{enumerate}
现在才有必要引入三个名称：查找需求叫 Query，
候选位置的匹配特征叫 Key，
被实际加权读取的内容叫 Value。

\subsection{三种角色是怎样从这两个任务长出来的？}
\phantomsection\label{concept:qkv}

把上面两个任务落实到数值计算，就得到三个角色：
\begin{itemize}
\item \textbf{Query（查询，记作 $\vect q$）：}
当前这个位置\textbf{拿什么条件来查}？它用于发起匹配。
\item \textbf{Key（键，记作 $\vect k_i$）：}
第 $i$ 个位置\textbf{凭什么被找到}？它与 Query 比较，
产生一个\textbf{匹配分数}。
\item \textbf{Value（内容，记作 $\vect v_i$）：}
第 $i$ 个位置\textbf{被找到后交出什么}？
它不是匹配分数，而是最终\textbf{被加权相加}的向量。
\end{itemize}

\begin{center}\QKVlegend\end{center}
因此\textbf{Q 和 K 是为了得到权重，V 是为了形成输出}。
刚才暂时写的“内容” $\vect c_i$，现在就改名为 Value $\vect v_i$；
\textbf{不是凭空新添了第三种数据}。

\input{figures/attention-why-qkv}

\textbf{三个名字不代表三个 Token。}在 Self-Attention 中，
第 3 个 Token 一方面能发出自己的 Query，
另一方面也像其他位置一样提供 Key 和 Value。
每个位置原本有一条输入表示 $\vect x_i$，
在真实网络中可以经过\textbf{不同的可训练投影}，得到
\[
\vect q_i^\top=\vect x_i^\top W_Q,\qquad
\vect k_i^\top=\vect x_i^\top W_K,\qquad
\vect v_i^\top=\vect x_i^\top W_V.
\]
这里约定每个 Token 的输入 $\vect x_i^\top$ 是\textbf{行向量}，
$W_Q:d_{\rm model}\times d_k$。若改写为列向量，
必须把权重也转置：$\vect q_i=W_Q^\top\vect x_i$，
而不是仍写 $W_Q\vect x_i$。
这三组参数以后才通过训练确定；
这里提前展示它们的来源，下一部分再亲自算投影矩阵。

\textbf{为什么不干脆只用一种向量？}
当然可以设计让 Query、Key、Value 使用相同表示的简化注意力；
但\textbf{用于判断相关性的特征}和\textbf{希望读出的内容}
不必一样，且 Value 的维度也不要求等于 Key 的维度。
把两项任务分开，是采用 Q/K/V 投影的重要理由，
\textbf{不是数学上必须使用三个不同矩阵的定理}。

打个类比：查资料时，问题像 Query、索引像 Key、
正文内容像 Value。但这只帮助区分\textbf{功能}；
真实模型读写的都是数字向量，不是在互联网搜索网页。

现在只进行\textbf{一次查询}：
位置 3 发出 Query，分别与位置 1、2、3 的 Key 匹配，
得到三条权重，再从这三个位置的 Value 读取内容。

\subsection{匹配：从 Query 和 Key 算出三个分数}

为什么能比较？因为前面已经学过\textbf{\hyperref[intro:02-dot-product]{点积}}：
把两个长度相同的向量对应位置相乘，再把结果相加。
这一步只为学习检索计算，\textbf{单独指定一组二维 Query/Key}，
没有指定生成它们的投影矩阵。特别是下方
$\vect k_1=(2,0)^\top$ \textbf{不是}前面“春天”的
Embedding $(1,0)^\top$：若要从 Embedding 计算 Key，
必须另外给出同一层共享的 $W_K$，不能直接把两组数当作同一张表。
\[
\vect q=\begin{bmatrix}1\\0\end{bmatrix},\quad
\vect k_1=\begin{bmatrix}2\\0\end{bmatrix},\quad
\vect k_2=\begin{bmatrix}0\\1\end{bmatrix},\quad
\vect k_3=\begin{bmatrix}1\\1\end{bmatrix}.
\]
第 $i$ 个位置的匹配分数定义为
$s_i=\vect q^\top\vect k_i$，即 Query 和该 Key 的点积。
一条条算：
\[
\begin{aligned}
s_1&=1\times2+0\times0=\boxed{2},\\
s_2&=1\times0+0\times1=\boxed{0},\\
s_3&=1\times1+0\times1=\boxed{1}.
\end{aligned}
\]
于是得到三个分数：
\[
\boxed{(s_1,s_2,s_3)=(2,0,1).}
\]

\textbf{请注意：这组分数不是凭空出现的。}
它们是\textbf{一个 Query 和三条 Key 各做一次点积}算出来的。
这些向量是人工挑选的，\textbf{不能把“春天”的语义天然等于 $(2,0)$}；
真实模型通过训练学习如何从 Token 表示生成 Q/K/V。

\subsection{分配：怎样把分数变成读取比例？}
\phantomsection\label{concept:softmax}

分数 $2,0,1$ 不能直接当作“读取的百分比”：
它们的总和不是 $1$，实际分数还可能出现负数。
我们希望得到三个\textbf{非负、加起来恰好为 $1$}的权重，
就使用\textbf{Softmax}：
\[
a_i=\frac{e^{s_i}}{e^{s_1}+e^{s_2}+e^{s_3}},
\qquad e\approx2.718.
\]
其中 $e$ 是一个数学常数，$e^{s_i}$ 表示指数运算，
$a_i$ 是\textbf{第 $i$ 个位置的读取比例}。
代入刚才的三个分数：
\[
\begin{array}{c|ccc}
\text{位置}&1&2&3\\\hline
\text{分数 }s_i&2&0&1\\
\text{权重 }a_i&0.665&0.090&0.245
\end{array}
\]
因为舍入，三个小数相加\textbf{约等于} $1$。
位置 1 的匹配分数最高，所以当前 Query 对位置 1 的
读取权重最大，但\textbf{其他位置并非完全被舍弃}。

\begin{warningbox}
Softmax 不是“找到唯一正确答案”，也不会验证文字事实。
它只是根据给定分数\textbf{分配一组权重}。
下一章会解释把 Softmax 批量写进矩阵时的形状与缩放规则。
\end{warningbox}

\subsection{读出：Value 怎么组合成一条新向量？}

现在才能回答 Attention 的输出是什么：
它并不是“位置 1”，也不是那三个分数，而是一条\textbf{新的信息向量}。

假设每个位置提供的 Value 也是两个数字：
\[
\vect v_1=\begin{bmatrix}1\\0\end{bmatrix},\quad
\vect v_2=\begin{bmatrix}0\\1\end{bmatrix},\quad
\vect v_3=\begin{bmatrix}1\\1\end{bmatrix}.
\]
把权重乘到\textbf{对应的 Value} 上，然后相加：
\begin{align*}
\vect y
&=a_1\vect v_1+a_2\vect v_2+a_3\vect v_3\\
&\approx0.665\begin{bmatrix}1\\0\end{bmatrix}
+0.090\begin{bmatrix}0\\1\end{bmatrix}
+0.245\begin{bmatrix}1\\1\end{bmatrix}\\
&=\boxed{\begin{bmatrix}0.910\\0.335\end{bmatrix}}.
\end{align*}
\textbf{这条二维向量就是本次 Attention 的读取结果。}
位置 3 可以拿它继续计算下一层，最终用于预测下一个 Token。
本章仅演示核心读取运算；真实 Transformer 还会处理投影、残差等步骤。

\begin{example}[title={为什么 Key 和 Value 必须区分角色？}]
保持 $\vect q,\vect k_1,\vect k_2,\vect k_3$ 完全不变，
\textbf{只}把位置 1 提供的内容改成
$\vect v'_1=(0,2)^\top$。
匹配分数依然是 $(2,0,1)$，
因此 Softmax 权重也\textbf{完全不变}；
但新的读取结果却变成
\[
\vect y'\approx
0.665\begin{bmatrix}0\\2\end{bmatrix}
+0.090\begin{bmatrix}0\\1\end{bmatrix}
+0.245\begin{bmatrix}1\\1\end{bmatrix}
=\boxed{\begin{bmatrix}0.245\\1.665\end{bmatrix}}.
\]
所以\textbf{Key 决定一条内容有多相关，
Value 决定最终取回什么数字}。
二者可以来自同一个 Token，但职责不能混淆。
\end{example}

\begin{example}[title={核对自己是不是理解了 Attention}]
假设位置 3 的 Query 改变了，三个分数也可能随之变化。
因此即使候选 Key/Value 没变，\textbf{不同 Query 得到的权重、
读出的向量也可以不同}。

思考：如果另一组权重是 $(0.1,0.8,0.1)$，
输出会是什么？根据同样的三个 Value，可以算出
$0.1\vect v_1+0.8\vect v_2+0.1\vect v_3=(0.2,0.9)^\top$。
它和刚才的 $(0.910,0.335)^\top$ 不一样：
\textbf{Query 改变，读取比例和结果就可能改变。}
\end{example}

\subsection{最后对照 RNN：差别究竟在哪里？}

\begin{center}
\small
\renewcommand{\arraystretch}{1.35}
\begin{tabularx}{\linewidth}{@{}p{33mm}XX@{}}
\toprule
比较的问题 & RNN & 本章的 Attention\\
\midrule
当前位置怎样利用前文？ & 接收上一时刻传来的状态 & 直接对多个候选位置匹配和读取\\
输出是什么？ & 更新后的状态向量 & 多条 Value 的加权组合向量\\
是否需要逐步传状态？ & 是 & 核心读取运算不需要这样递推\\
是否使用可训练参数？ & 可以，且通常共享更新参数 & Q/K/V 的投影在真实模型中可学习\\
\bottomrule
\end{tabularx}
\end{center}

还有三条重要边界：
\begin{enumerate}
\item \textbf{普通注意力不等于任意偷看未来。}
预测下一个 Token 时，只允许读取当前及此前可见的位置；
后面的\textbf{因果 Mask} 将明确实现这个限制。
\item \textbf{Attention 不等于无限长记忆。}
如果每个位置都和很多位置比较，计算量和存储会增长。
\item \textbf{本章只有一个 Query。}
真实 Self-Attention 会让\textbf{每个 Token 都发出自己的 Query}，
因此需要把重复运算写成矩阵形式。
\end{enumerate}

\begin{conclusion}
先记住\textbf{为什么}：
\textbf{要按当前需要读取前文，就得决定“读谁多少”和“取出什么”。}
在本书使用的点积 Attention 中，
Query 和 Key 产生相关性分数，Softmax 分配比例，
Value 是真正加权求和的内容。

你已经亲手得到：三个候选位置 $\to$ 三个点积分数
$\to$ 三个权重 $\to$ 一条输出向量。
\textbf{下一章唯一要新增的，是如何把同一运算更高效地组织成矩阵。}
\end{conclusion}

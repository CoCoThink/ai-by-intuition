# 部分开篇与收尾

本页说明每个部分首尾两页的设计与维护方式。文案都在 [book/part-maps.tex](../book/part-maps.tex)，累积复习 R 题由 [book/exercises.json](../book/exercises.json) 生成到 `book/part-reviews.tex`。

## 原则

**开篇只负责引入；回顾、答案和自测一律放在收尾。** 旧版开篇有“读完试试看”，读者翻开第一页就被要求完成一道读后总结题，时间顺序是反的。现在全书只有两层“读完”：章末自测和部分收尾。

序章放在第一部分之前，是全书的出发点；第一部分开篇接序章的问题。

## 开篇（一页之内）

| 元素 | 写法 |
|---|---|
| 为什么从这里开始 | 1–2 句，接上一部分（第一部分接序章）留下的问题。写读者能感到的具体问题，不写本部分第 1 章的论点。扩展路径（视觉、联想记忆）在这里写明“主线不依赖”。 |
| 先想一想 | 一道凭直觉就能答的题，单独放在浅蓝框里。框内固定提示“凭直觉答就行，本部分末尾会给出答案”。 |
| 学完你能做到 | 两条，用动作描述（算出、判断、说明、写出），只用读者此刻已经见过的词，不列术语清单。 |
| 本部分地图 | 章节入口与本章核心问题表。 |
| 全书路线 | 一行面包屑，当前部分用文字“（你在这里）”标出，不只靠颜色。完整九格路线图只在“怎么读”页出现。 |

## 收尾（接在本部分最后一章之后）

1. **回到开篇**：复述“先想一想”，用一句话给出答案，并以 `§x.y · 第 p 页` 链接到答案所在的小节。
2. **本部分累积复习**：生成器输出的两道 R 题。
3. **下一步**：一句话交代下一部分做什么；主线结束处说明后面是两条扩展路径。

## “先想一想”的三条规则

1. 只用读者此刻已经见过的词，即序章、前面各部分以及题目本身交代过的说法。
2. 凭生活直觉就能答；答不全对也没关系，但后文必须能证实或修正它。
3. 答案在**本部分**某一节。读者读到那里时，应能认出“这是在回答开篇的问题”。答案处标 `\phantomsection\label{partq:<部分键>}`。

## 源码结构

- 通用宏：`\partentry{为什么}{先想一想}{能做到}{地图行}`、`\partexit{部分键}{先想一想}{答案}{下一步}`、`\partbreadcrumb`。
- 每部分三条宏：`\partthink<键>`（题目只写一次，首尾共用）、`\partentry<键>`、`\partexit<键>`；`\partexit<键>` 内部调用生成的 `\partreview<键>`。
- [main.tex](../book/main.tex) 中每部分的顺序固定为 `\part{…}\label{part:<键>}` → `\partentry<键>` → 各章 `\input` → `\partexit<键>`。第九部分的框架来源署名紧跟在 `\partentrymemory` 之后。
- 引用其他部分时用部分名称加 `\hyperref[part:<键>]`，不写死“第八部分”；`\ref*{part:…}` 只会输出“八”。

## 检查

- `check_book_contract.py`：序章必须在第一部分之前；每部分恰有一对同键的 `\partentry`/`\partexit`；`partq:<键>` 必须定义在本部分的某一章文件里。`--self-test` 中有“第五部分的答案落在第四部分”的反例。
- `validate_book.py --pdf`：每个开篇页都要包含“为什么从这里开始”“先想一想”“学完你能做到”“本部分地图”“全书路线”“你在这里”；九个收尾（“回到开篇”加累积复习）各自落在本部分的页码范围内。

## 排版注意

- 开篇必须在一页内放下。增加文字后，先渲染九个开篇页再提交。
- 收尾块约 8–10 行，前面有 `\Needspace`。章末页剩余空间不够时，收尾会独占下一页，例如目前第二部分的收尾。这是部分结束页，可以接受，但改动后要目视检查有没有挤出更稀疏的页面。章末小结的分页检查会跳过只有收尾的页，只检查章节自身的结尾。
